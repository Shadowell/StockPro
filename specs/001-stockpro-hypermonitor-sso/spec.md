# 功能规格：StockPro 统一登录

**Feature Branch**: `codex/hypermonitor-sso-20261004`
**Created**: 2026-10-04
**Status**: 实施与无服务验证完成，待获准发布
**Input**: 用户要求通过 HyperMonitor 统一飞书登录访问 StockPro，保留原认证和机器权限。

## User Scenarios & Testing

### US1 - 已登录用户直接访问（P1）
已有有效中央管理员会话、没有本站会话时，打开 StockPro 直接进入工作台。
验收：两个登录态入口和受保护业务入口返回一致身份；重复、畸形、过期 Cookie 与异常中央响应不能授权。

### US2 - 旧入口与权限保持（P1）
原管理员、邀请码访客和 MCP 调用继续使用原有权限；有效访客会话不会因同时存在中央会话而升级。
验收：原会话与 MCP Token 优先；没有 Cookie 的伪造身份头无效；跨站写请求被拒绝。

### US3 - 登录与退出（P2）
登录页提供飞书统一登录入口，保留原登录表单；退出清除当前浏览器本站及共享会话 Cookie。
验收：统一登录回到固定 HTTPS StockPro 入口；退出不写 Paper 或 Live 数据。

### Edge Cases
中央 401、503、重定向、网络错误、错误数据结构、空用户、非管理员、重复 Cookie、跨站 Origin。
本站原会话无效时允许有效中央会话；中央 Cookie 缺失时不发起外部请求。

## Requirements

- FR-001：只信任固定中央 HTTPS 服务校验后的单个共享会话，不共享中央密钥，不信任外部身份头。
- FR-002：保留 MCP、本站管理员与访客认证优先级，中央会话仅作为备用管理员身份。
- FR-003：SSO 非安全方法在 Origin 存在时必须来自本站 HTTPS 源；退出共享 Cookie 同样限制来源。
- FR-004：中央异常时不得登录；无效中央会话返回未认证，服务不可用明确返回 503。
- FR-005：登录态探测两个兼容入口一致；提供统一登录按钮与浏览器 Cookie 退出。
- FR-006：本次不启动服务、不连接生产、不修改业务数据；只允许推送任务分支供审查，不合并或部署。

### Key Entities
中央会话仅产生当前请求身份：管理员角色、显示用户名、认证方式；不落库、不缓存长期授权。

## Success Criteria

- SC-001：所有正向及拒绝用例通过无服务回归，原认证基线保持通过。
- SC-002：已有中央登录的用户无需再次输入密码；原访客和机器权限保持不变。
- SC-003：退出响应清除两个 Cookie，后续无其他有效凭证的请求不再获得管理员身份。

## Assumptions

- 中央会话合同由 HyperMonitor 主任务提供；端到端上线验收等待中央端点部署及 StockPro 生产禁令明确解除。
- 本轮允许提交并推送任务分支供审查，不调用生产、不运行本地服务、不推 main；此授权覆盖旧本地重启流程。
- 需求、身份、优先级、失败与交付边界均已明确，无待确认歧义。
