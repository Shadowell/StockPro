# StockPro Constitution

## Core Principles

### I. 研究与模拟边界
必须保持 A 股研究与 Paper 模拟交易边界，不开放真实券商交易；认证改动不得修改业务账本。

### II. 最小可审查变更
必须在隔离任务分支实施，只提交本次改动，保留用户已有修改；沿用当前 PostgreSQL 与前后端合同。

### III. 认证失败关闭
不得信任客户端身份头、记录秘密或把错误当作已认证；管理员、访客与机器权限必须明确隔离。

### IV. 行为验证
认证及后端行为先写失败回归再实现。必须报告实际通过的检查，以及未完成的运行验收。

### V. 事实入口一致
长期接口与部署约定变更必须同步 docs/spec.md、当前合同与 docs/progress.md；过程日志留在对话。

## 安全与运行约束

凭证、Cookie、密钥、运行数据库不得入库。生产只走既有 Actions；当前 AGENTS.md 的生产部署禁令继续有效。
用户本次禁止启动本地服务时，采用无服务测试，不能暗中执行旧重启步骤或生产替代验证。

## 开发与交付

默认 specify → clarify → plan → tasks → analyze → implement → converge。
复用现有工具，规格保持简短。提交前检查差异、敏感内容与验证结果；推送与部署遵守当前授权。

## Governance

用户当前指令与 AGENTS.md 优先。修改原则需说明日期、适用范围与兼容性；版本按语义化版本维护。
本次首次接入保留 Spec Kit 1.0.6 上游模板，不覆盖原工作区 Agent 配置。
