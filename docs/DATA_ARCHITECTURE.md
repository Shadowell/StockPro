# StockPro 数据架构

> 更新日期：2026-08-28
> 数据库：PostgreSQL only
> 原则：来源可见、时间可解释、质量先于发布、快照不可变

## 1. 数据链路

```text
TuShare / AKShare
       ↓
Provider adapter 与权限检查
       ↓
标准化记录 + 来源/时间元数据
       ↓
PostgreSQL 未封存分区
       ↓
覆盖率 / 完整性 / 一致性 / 合法性检查
       ↓
不可变数据快照
       ↓
因子、股票池、回测、Paper Replay
```

页面、因子、回测和模拟盘优先读取 PG。页面 GET 不应为了填充空状态自动访问外部 Provider。

## 2. Provider 策略

### TuShare

主要用于：

- 证券主数据、中文简称与上市状态；
- 交易日历；
- 日线与指数行情；
- 复权因子；
- 日度估值与换手；
- 停复牌与涨跌停价格；
- 财务披露和公司行动；
- 获得授权的资金流、涨停生态和其他研究数据。

接口可用性取决于 Token、积分、单独权限和调用频率。权限不足必须显示为 `restricted`，不能返回看似成功的空数据。

生产合同要求每日全量刷新 A 股证券主数据（L/P/D，退市 `T*` 独立命名空间）、最近开放交易日日线和
`daily_basic`。页面展示证券时中文名称在前、标准代码在后；名称来自持久化证券主数据，不能维护三只或其他硬编码演示清单。

### AKShare

主要用于：

- 公开全市场快照；
- 概念/行业板块；
- 热门排行；
- 涨停池与公开短线生态；
- 公开新闻、事件和其他补充数据。

AKShare 不是无条件兜底。回退必须按一个完整数据集/日期发生，并记录来源与原因，不能逐行混合后仍标成同一来源。

## 3. 核心时间字段

| 字段 | 含义 |
| --- | --- |
| `trade_date` | 市场事实所属交易日 |
| `available_at` | 研究或模拟时最早允许使用的时间 |
| `knowledge_cutoff_at` | 快照包含信息的截止时间 |
| `collected_at` | StockPro 实际采集时间 |
| `source_updated_at` | 上游或持久化证据的更新时间 |
| `response_generated_at` | API 响应生成时间，仅用于传输诊断 |

财务数据按披露可用时间进入研究，不按报告期提前可见。日线数据只有收盘后才完整可用。

## 4. 数据目录与分区

数据目录记录：

- 数据集代码和中文名称；
- 业务模块与用途；
- Provider/端点；
- Schema 版本；
- 更新频率与计划；
- 权限要求和当前权限状态；
- 存储、缓存和导出规则；
- 最近同步、质量和发布状态。

每次同步写入任务和数据分区。分区至少绑定数据集、交易日、来源、采集时间、记录数、Schema 版本和质量状态。

## 5. 质量门

发布前检查按数据集定义执行，常见规则：

- 交易日和目标日期一致；
- 证券范围和记录数达到最低覆盖；
- 主键唯一；
- OHLC、成交量、价格上下限等字段合法；
- 缺失率和异常率在阈值内；
- 来源和 Schema 与目录一致；
- 关联数据集能够对齐；
- 不存在未解释的跨源混合。

质量失败的数据可以保留用于诊断，但不能封存为“可用于研究”的快照，也不能触发后续因子计算。

## 6. 数据快照

数据快照是研究输入边界，包含：

- 固定分区清单；
- 数据集与交易日范围；
- 股票范围/Universe；
- 来源和回退记录；
- 知识截止时间；
- 质量结果；
- 记录数、哈希和封存状态。

封存后不可修改。Provider 更正或补数通过新分区和新快照发布。旧回测继续读取原快照。

首页市场基础层和异动边缘使用 `market_evidence_snapshots` 作为市场证据边界。近半年历史同步完成时，
股票日线、沪深300基准、行业成员等权对照、最新日 `symbol_abnormal_metrics` 和 sealed
market evidence snapshot 必须在同一事务提交；任一步失败不得留下部分榜单或孤立 metrics。

## 7. Universe 与点时数据

Universe 快照需要保存：

- 股票代码、交易所和名称；
- 上市、退市、停牌和 ST 状态；
- 板块/行业分类；
- 指数成分关系；
- 状态的有效起止时间。

回测不能用今天的股票列表回填历史。股票是否存在、是否 ST、是否停牌、属于哪个指数，都必须按模拟时间判断。

## 8. 因子、股票池与回测

- 因子计算绑定数据快照，发布独立因子快照。
- 股票池绑定数据/因子证据，保存规则和入选原因。
- 回测绑定策略版本、数据、Universe、因子、股票池、研究协议和成本模型。
- 回测运行中禁止调用 TuShare/AKShare。
- 下游对象只引用已发布证据，不隐式“取最新”。

## 9. 实时与日终数据

### 日终

PG 调度默认面向收盘后任务。典型顺序：

1. 检查交易日；
2. 获取全量证券主数据和中文名称；
3. 获取最近开放交易日日线；
4. 获取 `daily_basic`、复权因子、估值/换手；
5. 获取停牌和涨跌停价格；
6. 获取沪深300等基准指数；
7. 更新行业/板块对照与市场证据；
8. 运行质量检查；
9. 原子发布数据快照；
10. 按配置触发后续研究任务。

任务使用 PG 锁和持久化水位，避免重复执行。最近交易日可按新快照方式对账更正。

管理员可显式触发近 180 个自然日全市场 A 股历史回补；任务先完成 Provider 请求，再一次性幂等写入，
并与市场证据快照和异动 metrics 保持事务一致。页面 GET 只读已物化结果，不临时同步、重算或写库。

### 实时

指数、全市场快照、板块、新闻和盘口按模块配置轮询或按需读取。实时数据与封存研究数据分开表达：

- 实时页面显示采集时间和新鲜度；
- 过期实时数据不能被响应时间刷新；
- 实时缓存不自动成为回测证据；
- 需要用于研究时先落 PG、检查并封存。

## 10. 数据中心状态

数据中心面向操作者展示：

- 研究数据是否可用；
- 最新交易日和知识截止时间；
- 阻塞研究的最高优先级问题；
- 数据集覆盖和质量；
- 同步任务进度与日志；
- Provider 权限；
- 日终计划与最近执行；
- 快照和表统计。

用户主阅读层不展示数据库主键、哈希、任务 UUID 或原始 Provider JSON。详情和审计层可保留内部标识。

## 11. 失败与恢复

- Provider 超时：任务失败或按合同进行整类回退，保存原因。
- 部分数据：保存未封存分区，不能发布完整快照。
- 进程中断：根据 PG 任务状态恢复或显式重试。
- 重复请求：通过幂等键、唯一约束和任务锁避免重复写。
- 数据更正：新分区、新快照，不覆盖已使用证据。
- PG 恢复：备份与恢复演练需核对快照清单、因子、回测和 Paper 账本。

## 12. 数据安全

- `.env`、Provider Token、数据库备份和导出文件不进入 Git。
- 数据库查询接口只允许白名单表和受控语句。
- Agent 写入遵循作用域、幂等和审计规则。
- 商业数据的缓存、导出和再分发遵循 Provider 授权。
- 远程数据库迁移或生产同步需要单独明确授权。

具体 API 见 [API 指南](api.md)，产品时间与快照规则见 [产品规格](spec.md)。
