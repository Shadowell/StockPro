# 策略中心页面合同

最终真实截图：[桌面](../screenshots/rebuild/strategy-1440x900.png) · [390px](../screenshots/rebuild/strategy-390x844.png)。

## 路由与当前 API

- 页面：`/strategy`。
- API：`GET/POST /api/strategies`、detail、子版本、`/api/strategies/validate` 和 quick-run。
- 公共产品不显示 API 版本或 migration 名称；历史合同字段仅在审计详情按需读取，禁止更新。

## 页面结构

- 策略目录使用 BitPro 卡片网格、搜索、状态筛选和 12 条分页；卡片显示最新不可变版本、
  代码状态、数据依赖、content hash、详情与回测入口。
- 详情抽屉显示版本/hash、A股执行语义、封存股票池/因子/数据/成本 lineage、参数 schema、
  代码、验证与创建子版本。
- A股固定提示 CN_A_SHARE、T+1、100股和只做多；具体策略可在完整合同中收紧，不能放宽
  市场规则。
- 新建策略与子版本写新 `strategy_versions`，不能覆盖被回测/Paper 引用的版本。

## 安全与晋级边界

- AST 只允许 initialize/handle_data 生命周期、声明 API 和安全 builtins；禁止 import、文件、
  网络、数据库、系统时钟、eval/exec 和未声明未来日期。
- validation 与 quick-run 使用同一隔离 worker 和 CPU/内存/时长/输出限额。
- quick-run 固定 `promotion_status=not_evaluated`；目录、代码有效或快速预检都不产生 Paper
  晋级资格，必须进入完整回测协议。
- GET 只读，不运行策略、Provider、scheduler 或 Paper recovery。

## 验收

- 后端合同测试覆盖无公共版本命名、历史 metadata 只读、quick-run 不可晋级和旧路径 404。
- 真实隔离库读取 63 个目录项、67 个版本；默认详情不暴露历史 metadata，审计详情可读，
  代码验证无业务写入、Provider imports 0。
- Mock E2E 覆盖目录、搜索、详情、封存输入、100股/T+1 与回测入口。
- 真实首页 12 卡分页、详情桌面/390px、console errors 0、六张策略/Paper 表计数不变；
  截图位于忽略目录 `frontend/output/playwright/wave3-strategy-real-*.png`。
