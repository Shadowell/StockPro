# 股票池页面合同

最终真实截图：[桌面](../screenshots/rebuild/pools-1440x900.png) · [390px](../screenshots/rebuild/pools-390x844.png)。

## 路由与职责

- 页面：`/arbitrage`；`/pools` 仅保留兼容重定向。
- 当前 API：`/api/v2/arbitrage/*`。
- 股票池是策略与回测的封存证券输入 Owner；页面不维护第二份证券列表，不允许回测直接
  引用未封存成员。

## 页面结构

- 左侧规则目录显示 pool type、当前成员数、封存数和最新交易日。
- 右侧规则详情显示状态、不可变规则版本/hash、最新 generation、data purpose 与完整 config。
- `成员与证据` 表显示 ordinal、证券、score、reason 和 evidence hash；名称只通过证券缓存
  补充，不改变成员 symbol。
- `封存快照` 显示 sealed/draft、trade date、member count 和 manifest hash。
- 新建规则、生成批次与封存是三个显式动作。生成表单必须提供 trade date、dataset snapshot
  和 universe snapshot；factor/market evidence snapshot 按规则需要填写，不自动选择最新。

## 不可变与数据边界

- `stock_pool_rules` 每次创建新版本，完成 generation 和 sealed snapshot 由 PostgreSQL trigger
  拒绝更新/删除。
- Generation 只绑定封存 dataset/universe/factor/market evidence；成员保存 reason、evidence、
  evidence hash、有效期和 generator version。
- Snapshot 从成功 generation 复制成员并计算 manifest hash；未成功 generation 不能封存。
- 页面 GET 只读，不能生成成员或快照；Provider 模块仅在明确生成动作需要时延迟加载。
- 无规则、无 generation、无成员和无 snapshot 分别显示诚实空态。

## 验收

- API 合同测试覆盖当前路径、创建→生成→封存调用边界和旧版本路径 404。
- 真实隔离库读取 6 个规则、6 个 generation、68 个成员、5 个 sealed snapshot，读取前后
  六张股票池表计数不变，TuShare/AKShare 未导入。
- PostgreSQL 真实 trigger 测试确认 sealed snapshot 即使写回相同 member_count 也被
  `immutable` 拒绝并回滚。
- Mock 页面 E2E 覆盖目录、成员 evidence、sealed snapshot 和加载时 0 mutation。
- 真实桌面/390px 页面、console errors 0、业务写入 0；截图位于忽略目录
  `frontend/output/playwright/wave2-pools-real-*.png`。
