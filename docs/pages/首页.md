# 首页页面合同

## 路由与定位

- 路径：`/`。
- 侧边栏：`首页` / `LayoutDashboard`。
- 首页是传统金融操作台总览入口，汇总指数、市场宽度、涨跌停生态、板块资金证据与
  策略→回测→模拟主线状态；不承载数字资产账户、实盘或链上能力。

## Wave 2 当前实现

页面只调用 `GET /api/market/overview`，数据流固定为当前 API →
`ResearchApplicationService` → `PostgresRepository`：

- 顶部 `Market Command` 显示 PostgreSQL evidence、CN A-share、data status 和只读刷新。
- `主要指数` 显示上证指数、科创50、深证成指、创业板指的缓存值、涨跌和证券代码；
  点击后进入行情页并通过 URL 传递 symbol。
- `市场宽度` 显示封存交易日的上涨/平盘/下跌与全市场缓存成交额。
- `涨停生态` 显示涨停、跌停、最高板和由封板率推导的炸板率。
- `板块资金` 只显示同一封存快照的 sector evidence；当前隔离库没有板块净流入行时显示
  明确不可用，不用涨停成员或随机行业补齐。
- `主线状态` 保留策略、回测、模拟的 Owner 入口，未进入 Wave 3 前标记待适配；不把
  Paper 基线存在误写成运行已恢复。
- 页脚显示 source label、交易日和更新时间。

## 数据状态合同

- Loading 使用稳定 skeleton；overview 请求失败显示核心错误面板。
- `empty`、`partial`、`stale`、`fresh` 直接展示在状态 badge，不改写来源判断。
- 可选板块数据缺失只影响板块模块；指数、宽度、涨停和主线入口继续显示。
- 数值 `null` 显示 `—`，不得变成 0；Decimal 通过 API 字符串传输，展示层显式验证再格式化。
- GET 不写库、不调用 TuShare/AKShare、不触发同步、快照、Provider、scheduler、策略或
  Paper recovery。

## 布局合同

- 继承 BitPro 的近黑画布、低对比卡片、细边框、蓝色交互强调、紧凑数字和稳定 KPI 网格。
- 使用 `text-up` / `text-down`，遵循运行时红涨绿跌设置，不在组件逻辑中硬编码颜色语义。
- Desktop 使用全宽信息带与数据网格；窄屏改为纵向卡片，不挤压数值列，不产生页面级
  横向溢出。
- 不使用营销 Hero、装饰性渐变、虚构在线状态或长篇功能说明。
