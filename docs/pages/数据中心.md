# 数据中心

最终真实截图：[桌面](../screenshots/rebuild/data-1440x900.png) · [390px](../screenshots/rebuild/data-390x844.png)。

`/data` 区分 PostgreSQL 缓存、发布分区、封存研究快照、Provider 权限、同步任务、质量问题
和扩展数据暂存。

- 页面保留 BitPro `DataManager` 的“数据管理中心”页头、KPI、横向工作区和密集表格节奏，
  但标的范围来自 PostgreSQL `instrument_definitions`，不再使用三个硬编码示例。
- TuShare 每天北京时间 18:10 一次性同步全部 A 股证券主数据、最近开放交易日日线与
  `daily_basic`；`a_share_daily_sync_runs` 记录开始、成功、失败、日期和行数，并以唯一 running
  门禁阻止手动与定时任务并发。证券主数据同时保存上市状态、行业、板块和中文简称。
- 所有证券选择与主要交易证据组件统一按“中文名称在前、标准代码在后”显示；名称缺失时明确
  显示“名称待同步”，不把代码伪装成名称。搜索同时匹配中文名称与代码。
- 八个工作区固定为总览、研究数据、行情覆盖、同步任务、Qlib导出、数据源、质量和导入导出；
  状态先读，其余证据使用 `Promise.allSettled` 分块加载，一类慢/失败不拖垮整个页面。
- 总览明确显示封存研究快照与可信边界；研究数据区分 TuShare 主源与 AKShare 整类回退；
  Qlib、质量和导入写操作只在管理员明确点击后执行。
- 页面 GET 不触发 Provider、同步、质量、迁移或封存。
- `/api/v2/sync/ashare/dataset-foundation` 只读展示 A 股 canonical 数据集目录、
  Provider 权限、本地分区覆盖、封存快照可用性和安全边界；缺分区、质量阻塞或未封存时
  明确返回 blocked，不把缺失数据标成 ready。
- TuShare 是主源；AKShare 只作为显式整类回退，来源在分区/fetch run 中留痕。
- 扩展 CSV/JSON/XLSX 只进入 `staged_only` 表，未映射、不可执行，不会自动进入策略、因子、
  回测或 Paper。HTTPS 导入要求精确 allowlist、公共 DNS 且禁止重定向。
- 访客只读；管理员可显式触发全量 A 股同步。每日计划由生产环境配置管理，不允许页面把同步
  范围缩减为少数自选标的。
- “拉取近半年 A股”按 TuShare 交易日历覆盖最近 180 个自然日，接口立即返回任务号；页面显示
  已扫描交易日与待写入行数，全部取数成功后才原子 upsert，服务或 Provider 中断不会留下半批历史。
- `/api/v2/sync/assets` 以 5,550 个活动 A 股为分母返回每只证券的 1D `row_count/from/to`；
  顶部记录数、数据对数和逐标的求和使用同一合同。页面每页 200 只，可访问全部标的，不再只渲染前 200。
- 全量 A 股由统一同步任务维护时，逐标的删除、增量和按日期补数入口保持禁用并说明原因；
  危险移除入口不为 5,550 个活动证券重复展示。
- 近半年同步同时物化沪深300基准、行业成员等权对照、sealed market evidence snapshot 和最新日
  3/10/30 日 `symbol_abnormal_metrics`；首页和行情异动页只读这些已物化结果，不在 GET 中重算。
