# 数据中心

最终真实截图：[桌面](../screenshots/rebuild/data-1440x900.png) · [390px](../screenshots/rebuild/data-390x844.png)。

`/data` 区分 PostgreSQL 缓存、发布分区、封存研究快照、Provider 权限、同步任务、质量问题
和扩展数据暂存。

- 当前 BitPro `DataManager` 整体源码作为不可达参考保留；默认页面复用其“数据管理中心”页头、
  KPI、横向工作区和密集表格节奏，但唯一调用 `dataCurrentApi`，不注册 OKX 原生同步。
- 八个工作区固定为总览、研究数据、行情覆盖、同步任务、Qlib导出、数据源、质量和导入导出；
  状态先读，其余证据使用 `Promise.allSettled` 分块加载，一类慢/失败不拖垮整个页面。
- 总览明确显示封存研究快照与可信边界；研究数据区分 TuShare 主源与 AKShare 整类回退；
  Qlib、质量和导入写操作只在管理员明确点击后执行。
- 页面 GET 不触发 Provider、同步、质量、迁移或封存。
- `/api/v2/sync/ashare/dataset-foundation` 只读展示 A 股 canonical 数据集目录、
  Provider 权限、本地分区覆盖、封存快照可用性和安全边界；缺分区、质量阻塞或未封存时
  明确返回 blocked，不把缺失数据标成 ready。
- TuShare 是主源；AKShare 只作为显式整类回退，来源在分区/fetch run 中留痕。
- 扩展 CSV/JSON/XLSX 只进入 `staged_only` 表，未映射、不可执行，不会自动进入策略、因子、
  回测或 Paper。HTTPS 导入要求精确 allowlist、公共 DNS 且禁止重定向。
- 访客只读；管理员可显式创建同步/质量 pending job、修改计划或暂存扩展文件。
