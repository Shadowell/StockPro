# 首页页面设计

## 路由

- 路径： `/`
- 组件： `frontend/src/pages/Home.tsx`
- 侧边栏标签/图标： `首页` / `LayoutDashboard`

## 页面目的

首页是操作者进入系统后的市场大盘入口，只展示市场广度、榜单和系统上下文，不承载完整交易对浏览器，也不把套利作为单独菜单页面。

## 首屏布局

- Dark financial shell inherited from `MainLayout`.
- 顶部使用紧凑的 `Market Command` 市场指挥台标题栏，持续显示 `OKX PUBLIC DATA`、`USDT-SWAP` 与 `24H MARKET PULSE` 数据上下文；它是操作台状态栏，不使用营销式 Hero、虚构在线状态或账户数据。
- Market overview is the primary data section. The first module is a compact `OKX 市场概览 · 大盘情绪指数` grid: one large综合分 card plus market breadth, turnover, strongest/weakest symbols, and five sentiment cards in the same visual block. It must avoid long explanatory paragraphs, duplicated section titles, or a standalone `OKX 市场榜单` description card. The overview, `热门榜`、`涨幅榜` and `跌幅榜` use all currently active OKX USDT perpetual contracts, show an `全部 USDT 永续` scope badge, and fetch paginated results so the count is not silently capped at 50 or 500 rows. The OKX-app-style ranking board remains below it with `热门榜`、`费率榜`、`新币榜`、`TradFi`、`涨幅榜`、`跌幅榜`; the ranking board uses a two-column desktop layout: the left side is the compact榜单 selector, and the right side is the selected榜单 detail table. Ticker tabs show latest price, 24h change, sparkline, 24h volume, 24h turnover, and 24h range; `费率榜` shows OKX current funding rate, annualized estimate, next funding time, mark price, and exchange. Each ranking tab shows Top 10 rows inside a fixed-height internal scroll body.
- `大盘情绪指数` sits inside the fused overview module and computes a 0-100 summary score from real OKX ticker breadth/turnover plus OKX funding-rate data when available. It breaks the score into five compact operator-facing cards: `市场热度`、`杠杆情绪`、`多空拥挤`、`风险偏好`、`宏观事件`.
- 大盘情绪模块下方展示 `板块热度图`。桌面端采用“方块图 + 板块动量侧栏”的稳定双栏结构，窄屏纵向堆叠；侧栏从同一聚合结果展示真实领涨/领跌板块及按绝对涨跌排序的六个强弱板块，不发送额外请求。热度图复用已经逐页合并的全部活跃 OKX USDT 永续 ticker；矩形面积代表板块标的数，颜色代表板块成分 24h 等权平均涨跌。矩形直接显示板块名、标的数和整体涨跌，悬浮展示上涨/下跌/平盘家数与强势成分。点击任一矩形后在模块下方展开该板块全部标的的行情表，显示最新价、24h 涨跌、成交额、最高和最低；当前板块持续高亮，可关闭或点击其他板块切换，明细行点击后进入对应行情页。
- 首页使用克制的数据动效辅助识别刷新：综合分、上涨家数、下跌/平盘数字使用滚动过渡，概览与情绪卡首次进入时轻微淡入上移；板块热度图以稳定板块 ID 对面积、位置和颜色变化执行平滑更新，并在悬浮时突出当前板块。所有动效必须遵循系统 `prefers-reduced-motion`，不得改变真实数据、延迟操作或持续制造无意义运动。
- 板块热度图下方展示 `加密原生数据` 模块（`NativeDataPanel`）：BTC/ETH/SOL 三列核心币卡片，每列展示 taker 资金流买入占比（相对中性 50% 的偏移着色）、多空账户比、最新资金费率与 OI 最新快照及 24h 变化；数据全部来自已落库的真实数据（`okx_rubik_stats`、`funding_rate_history`、`open_interest_history`），缺失指标如实显示 `—`，不虚构数值。
- `加密原生数据` 模块底部为 `数据管道积累` 状态行：如实展示五个数据源（OKX 资金流、多空账户比、资金费率、OI 前向积累、OI 回填）的行数与时间覆盖，反映真实数据边界；涨跌语义色通过 `text-up`/`text-down` 呈现。
- 每个 ticker 的板块来自后端版本化分类表并返回 `sector_key`、`sector_name`、`taxonomy_version`；未维护的新标的进入 `其他`，因此板块标的数之和必须等于首页行情总数。分类只用于观察，不改变策略或交易行为。
- The `市场热度` card surfaces turnover concentration and must not repeat the overview band's `上涨家数` count.
- The sentiment module must not invent unavailable data. Long/short account-ratio and economic-calendar integrations are labeled as pending/read-only reminder inputs until real backend sources are wired.
- The page must not render the full trade-pair browsing table, search, favorite toggles, or the `合约 / 现货 / 币币 / 自选` tabs. The Home ranking detail table is limited to the selected Top 10榜单 rows.
- Summary cards and ranked market panels must use real OKX ticker-backed data. `新币榜` and `TradFi` only show configured symbols that the market API actually returns; they do not fabricate rows when OKX data is missing.
- Ranking rows use the shared `SymbolIcon` treatment: try public crypto logo assets first, keep fixed-size cells, and fall back to deterministic local letter badges for unsupported new listings, commodities, stocks, or failed logo loads.
- 榜单明细的 `标的` 列必须为排名、图标、标的名和 `SWAP` 标签保留稳定宽度；标的名优先展示完整名称，只有在极窄视口或横向滚动区域不足时才截断，并通过 `title` 保留完整文本。
- 榜单明细的数值、走势和区间列必须与标的主信息行顶部对齐，使 `SWAP` 标签、最新价及其他数值保持同一视觉高度；不要按包含副信息的整行垂直居中。
- 所有榜单明细的列标题使用中等字重、轻微字距、抬升的深灰蓝背景与上下分隔线，和数据行保持足够对比；标题栏保持吸顶，字段与列宽不变。
- 榜单选择器使用持续可见的左侧蓝色选中轨道、深色层级背景和 `Market Ranking` 操作台标签；选中态不得只依赖短时动画或低对比底色。

## 数据来源

- OKX public ticker data through BitPro market APIs.
- 首页全市场行情使用 `GET /api/v2/market/tickers?quote=USDT&market_type=swap`：服务端先解析当前活跃的 OKX USDT 永续合约，再按分页返回；前端逐页合并完整结果。`费率榜`仍使用独立的受控 funding 标的集，避免逐标的费率读取拖慢首页。
- `GET /api/v2/market/tickers` 以新增字段方式返回板块元数据；首页不为热度图发送额外行情请求。
- 前端请求层会把接口的 `sector_key`、`sector_name`、`taxonomy_version` 规范化为 camelCase；首页映射同时兼容 camelCase 与原始 snake_case 字段，避免分类存在却被误判为 `其他`。
- OKX USDT 永续 ticker 必须直接使用一次 SWAP 批量请求，不能先读取全市场 ticker 后再重复读取 SWAP；相同标的集合允许复用 15 秒进程内快照，以吸收短时间内切走再切回首页的重复请求。
- Contract ranking turnover uses quote-currency/USDT turnover. For OKX contract tickers, raw `volCcy24h` is base-asset volume, so BitPro must use the quote turnover field when available or derive `last * volCcy24h`.
- OKX funding-rate data through the existing BitPro funding API for the leverage sentiment card and the `费率榜` inside `榜单列表`.
- `加密原生数据` 模块通过 `GET /api/v2/market/native-sentiment` 只读聚合已落库数据：`okx_rubik_stats`（taker 资金流、多空账户比）、`funding_rate_history`（OKX 最新资金费率）与 `open_interest_history`（OI 最新快照及 24h 变化，优先 binanceusdm 回填序列）；端点不做外部网络请求。
- The Home summary does not expose favorites; symbol selection continues through ranking rows or the Market page detail selector.

## 交互规则

- Ranking detail row clicks navigate to `/market` and select the clicked symbol, including `费率榜` rows.
- 板块热度图矩形点击后展开该板块全部标的行情；板块明细行点击后同样进入 `/market` 并选中对应标的。
- Home does not expose per-symbol search, sortable market table, or favorite toggles.
- Entry cards navigate to specialist pages instead of opening deep modal workflows on the home page.

## 空态和错误态

- If market data is unavailable, show an explicit loading/error state; do not fill overview panels with synthetic tickers.
- 热度图加载中显示聚合状态；没有 ticker 时显示明确空态，不绘制空矩形或模拟板块。
- The page should still render navigation and static entry points when a secondary data block fails.
