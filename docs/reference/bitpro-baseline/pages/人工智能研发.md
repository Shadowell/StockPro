# AI研发页面设计

## 路由

- 路径： `/ai-lab`
- 组件： `frontend/src/pages/AILab.tsx`
- 侧边栏标签/图标： `AI研发` / `Sparkles`

## 页面目的

AI研发汇集自动交易 Agent、受控策略研发、AI 自主模拟盘、真实 OKX Orbit 发帖和既有策略优化。它是研究与操作者复核界面，不是绕过实盘边界的入口。

## 首屏布局

- Default tab opens the automatic trading-agent workspace.
- Tabs expose research, optimization, autonomous trading, and Orbit posting workflows without changing the page shell.
- Workbench cards use the same dark financial style and compact action buttons as other pages.
- 新策略研发 Tab 是独立的 ResearchWorkbench 模块，不再渲染旧的一次性策略猎手控制台。顶部固定展示 HyperTrade 连接/同步状态，以及 HT 研究中、回测结果、验证通过和模拟盘待处理四项指标；上游不可用时显示真实脱敏错误。
- 顶部状态数值使用独立抬起的 KPI 指标卡，不使用内凹黑底容器；对象型真实字段优先提取可读标量，无法归约时明确显示“已记录”，不得渲染 `[object Object]`。
- 研发主体使用四阶段可点击轨道：提议方向 → HT 研究回测 → 回测结果 → 模拟盘决策。宽屏横向连接、窄屏纵向排列；研究章程、StrategySpec、数据/代码校验、回测矩阵和验证门禁仍由 HT 内部受控执行，不再作为要求操作者逐项操作的前台节点。
- 顶部主操作为“提交研究提议”。提交后 BitPro 代理依次建立内部研究范围、创建任务并自动运行 HT 研究回测；页面不显示创建/暂停章程、生成草案或手动运行任务按钮，也不显示直接启动模拟盘、自动暂停、自动退役、自动实盘晋级、自动调仓或资金分配操作。
- 提交研究提议等工作台弹窗始终可通过右上关闭按钮、取消按钮、点击遮罩或 `Escape` 关闭；关闭只丢弃当前未提交表单，不执行研究、模拟盘或复核写操作。
- 提议弹窗只要求真实标的范围、周期、研究类型和一段提议方向；内部研究名称、章程和任务 ID 由系统生成。请求失败原因始终显示在当前弹窗内，取消/关闭不会执行写操作。
- 提议标的范围默认选中 `BTC / ETH` 永续，并通过 BitPro `GET /api/v2/market/symbols?exchange=okx&quote=USDT&market_type=swap` 读取真实可选范围；操作者可搜索、逐项多选/取消，已选项目以可移除 chip 展示。保留完整统一格式的手动加入入口；加载失败或无结果必须显示真实原因，不能用演示标的替代。
- 新策略研发工作台不展示旧 `strategy-assistant` 研发记录，也不在该页面提供其读取或删除入口；历史数据与既有后端接口保持兼容，不因隐藏工作台区块而删除。
- Model selection is drawn from server-side global LLM model settings.
- AI自主交易 tab 默认展示 Hermes / Codex 提供方、`gpt-5.5`、`多空双向`、系统 Top30 OKX USDT 永续候选池和 100U paper-only 风控信封，最高杠杆上限为 `10x`；默认单笔上限 `60%`、总敞口上限 `360%`、最多持仓 `6` 个、最小开仓名义 `50U`、每小时最多 `6` 笔，DashScope / Qwen 仍作为备选提供方。
- AI自主交易默认提示词强调通过 Hermes 调用 Codex、只做 OKX USDT 永续合约模拟盘、禁止实盘和真实账户动作，并把目标限定为在硬风控内提升模拟盘净收益：优先选择强弱分化清晰、成交活跃、流动性和波动足以覆盖手续费/滑点的标的，由 AI 在默认 `5-10x` 范围内自主决定杠杆，并在硬风控内自主决定仓位比例，用 `open_long/open_short` 验证多空机会；提示词同时声明默认最多 `6` 个持仓和最小开仓名义 `50U`。
- The `星球发帖` tab uses a compact control-room layout: top metrics for eligible positions, trigger threshold, scan interval, per-run cap, and Orbit login status; a left config panel for single-account automation; a right candidate/history panel for auditable posting.
- 默认 `自动交易Agent` 及其他非 `星球发帖` Tab 不读取 Orbit 私有持仓、候选或浏览器登录状态；只有进入 `星球发帖` Tab 才加载这些数据。候选预览允许复用 15 秒短缓存，配置修改和发布后必须失效；自动发布扫描必须强制读取最新持仓。

## 数据来源

- Agent research run APIs and persisted agent tasks.
- 新策略研发仅调用 BitPro /api/v2/research-workbench/*；BitPro 服务端以环境中的 HyperTrade 地址和管理员会话访问上游，浏览器不接触 HyperTrade 地址、cookie、token 或数据库。中文操作理由在出站 HTTP header 中使用明确标记的 UTF-8 percent-encoded 值，BitPro 审计保留原文；编码问题显示为受控代理错误而非“服务器内部错误”。
- 研发工作台仍通过摘要读取内部研究范围、任务/报告、候选证据、手工模拟盘晋级、纸面复核队列和 paper_snapshot 会话，但前台只按四阶段聚合展示。单策略纸面证据只使用同一不可变会话的 paper_snapshot，不拼接 dashboard、events 或 equity curve。
- Optional Hermes bridge state when configured server-side.
- Hermes/Codex 自主交易决策来自服务器本地 Hermes Bridge，必须返回 JSON-only 决策；UI 不保存 Codex 凭据或 API Key。启动/API 入参可使用 `hermes/grok` 或 `hermes/codex`，后端统一归一为 `hermes`。同一 AI 自主交易实例的连续决策复用同一个 Hermes `session_id`，该 id 由后端从 Hermes quiet 输出提取并持久化到策略运行态；服务重启恢复后继续复用，页面不展示或编辑该内部 id。
- Strategy optimizer config/results.
- OKX Orbit auto-post config, eligible live contract-position candidates, login status, and post history from `/api/v2/agent/orbit-auto-post/*`.
- Global LLM model settings from backend settings APIs.
- Real market snapshots for auto-collected research; no synthetic opportunities.
- Real OKX private live positions for Orbit candidates; no mock/fabricated PnL, ROI, chart, or engagement data.

## 交互规则

- Automatic research runs persist and can resume after backend restart.
- Automatic research runs and scheduled runs default to `preferred_direction=auto`, so long and short candidates can both enter the Hermes deep-research flow; an explicit long/short preference may still filter the candidate set.
- 新策略研发的 StrategySpec 永远先作为 HT 内部草案，未通过数据/代码校验、回测矩阵和全部验证门禁前不能表示为可运行策略。候选行显示 BitPro 策略 ID、版本、数据窗口、样本内/验证/锁定样本外、收益/回撤/交易数、成本假设、门禁、未通过原因、数据缺口与回测引用；`rejected` 等技术状态必须显示为中文结论。
- 只有 evidence_recorded 且所有门禁通过的候选才能显示“申请模拟盘”；审批必须填写理由和唯一幂等键。审批前工作台不会调用任何直接模拟盘配置或启动接口。
- 观察阶段只提供查看证据、跳转模拟盘详情、复制审计引用和触发只读采样。数据缺口或告警只展示 request_paper_review、request_pause_review、retire_candidate_review 等人工复核建议，不执行暂停、停止或退役。
- 策略档案与组合审阅继续由后端 API 保留，简化工作流默认不再单列底部 StrategyCard 区域；数据缺口和告警的前台建议仍只允许 request_paper_review、request_pause_review、retire_candidate_review。
- AI自主交易启动和编辑表单展示提供方、模型、交易方向、单笔仓位、总风险敞口、最多持仓、决策间隔、交易次数、试单仓位和初始资金。`多空双向` 允许在 paper 风控信封内执行 `open_long` 和 `open_short`；可选 `只做空` 仍由后端策略运行时强制执行，因此任何 `open_long` 建议都会变成已记录的风控拒单。
- Accepted candidates return to normal strategy/backtest/simulation flows.
- Live execution still requires `/live-real` preflight and confirmation.
- Orbit posting can be enabled/disabled, thresholded by margin ROI, manually run once, and manually publish a selected eligible candidate.
- Orbit copy can use the selected Qwen/DashScope model, but must preserve true position facts and include risk wording.
- Orbit publishing depends on the server-side browser publisher command and persistent OKX login profile; login/config failures are shown in status/history and do not count as successful cooldown events.

## 空态和错误态

- Missing LLM/model/Hermes configuration must show explicit blocked states.
- HyperTrade 未配置、上游权限拒绝、数据缺口、404/409/5xx 或超时必须在研发 Tab 显示真实脱敏原因；加载与空态说明进入下一阶段所需的真实条件，不能产生演示候选、虚构收益或占位策略。
- No-market-snapshot or model failures must not produce fake trade intents.
- Missing OKX Orbit login or publisher configuration must show explicit `login_required` / failed states and must not mark a post as published.
- No eligible live contract position should show an empty candidate state, not generated demo content.
