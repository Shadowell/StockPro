# 链上研究页面设计

## 路由

- Route: `/onchain`
- Frontend owner: `frontend/src/pages/OnchainResearch.tsx`
- Backend owner: `backend/app/api/v2/endpoints/onchain.py`
- Contract: `docs/contracts/链上研究看板.md`

## 页面目的

`链上` 是投资研究导向的链上数据看板。首版帮助操作者快速观察 DeFiLlama 覆盖的链 TVL、协议 TVL、协议费用、稳定币供给和稳定币收益池，从宏观资金流、协议基本面和收益机会三个角度筛选后续研究方向。

页面只读，不创建策略、不启动同步任务、不连接真实账户、不把链上指标自动注入交易逻辑。

## 首屏布局

- 顶部标题为 `链上数据`，使用全站标准 `text-2xl` 加粗标题与 `Network` 图标，标题下方一行灰色中文副标题；右侧紧凑展示 `全链视图`、`DeFiLlama` 中文状态（状态点带呼吸动画）、`更新于` 时间与 `自动刷新 mm:ss` 倒计时、`刷新` 按钮，头部控件统一使用 `rounded-xl` 圆角与全站按钮一致。页面每 5 分钟自动拉取一次 summary（后端有 30 分钟缓存），手动刷新会重置倒计时。
- 页面使用全宽 `p-6 h-full` 工作台布局，直接进入数据看板，不做营销 hero。所有模块面板（Panel）统一 `rounded-xl` 圆角、白色模块标题，标题下必须有一行灰色中文说明（一句话讲清这个模块看什么），内部行控件保持 `rounded-lg`。
- 顶部 KPI 栅格展示 `总锁仓量`、`稳定币供给`、`24H 协议费用`、`稳定币收益池`、`最大公链` 和 `最大协议`。KPI 卡保持全站克制风格：中性 `crypto-border` 边框与 `bg-crypto-card` 卡体、白色 `tabular-nums` 数值，依靠底部色条和副标题语义色区分资金、稳定币、费用、收益池、链和协议六类，不使用右上角装饰图标；数字类 KPI（锁仓、供给、费用、收益池数量）在刷新时使用滚动过渡动画，副标题写解释性文案（如「覆盖 N 条公链的锁仓资金」）。
- KPI 下方首屏采用左侧主研究区、右侧诊断栏的两栏结构。`综合总览` 主研究区自上而下：`资金流水线 · 链 → 协议`（echarts Sankey：全链 TVL → 锁仓量前 8 条公链 → 每链头部 3 个协议，连线越粗资金越大，悬停看金额，加载时流动绘制）、`链锁仓量 Top 10` 横向条形图，然后是链锁仓量与稳定币供给两张表格。左侧顶部是中性边框的紧凑工具条（不额外叠加青色调），包含 `综合总览`、`协议研究`、`收益机会` 分段控件，以及内联 `链上术语` tooltip；分段控件和本地观察选择的选中态统一使用黄色底色，不再把术语做成独立大空卡。
- 主研究区各表格的数字列（锁仓量、供给、费用、年化、变化等）右对齐并启用 `tabular-nums`，文本列保持左对齐；表格使用内部滚动，保证宽窄屏下页壳稳定。链锁仓量、协议、收益池三张主表的行进入时按索引错峰淡入（`row-enter`，尊重 `prefers-reduced-motion`）。
- 关键列头（锁仓量、锚定状态、1日/7日变化、费用/TVL、年化收益、30日均值、风险状态）必须带原生 `title` 悬停解释，用一句话说明该列怎么看；链锁仓量表不再展示 `链编号` 这类对研究无意义的列。
- 右侧诊断栏固定承载 `数据源健康`、`风险提示` 和本地 `观察清单`，三个面板都带一句说明。数据源按行展示中文数据集名和状态；风险按红、amber、emerald 语义块区分优先级，文案必须是可执行的大白话（如「N 个稳定币价格偏离 1 美元，注意脱锚风险」「N 个收益池年化异常偏高，可能是高风险信号」），观察清单只显示当前页星标的真实行。
- `综合总览` 默认在主研究区展示资金流水线、链锁仓量 Top 10 条形图、链锁仓量表和稳定币供给表。链和协议/收益池行右侧提供星标按钮，只把当前真实 API 返回行加入本页本地观察，不写入后端、不创建策略。
- `协议研究` 展示协议锁仓量、协议费用排行、协议类别/链筛选、文本搜索、排序和 `费用/TVL` 年化效率列。收益和变化使用 `text-up` / `text-down` 跟随全站涨跌配色。
- `收益机会` 展示稳定币收益池与稳定币链分布，并支持链、风险状态和排序筛选。收益池风险状态由当前行的 APY、30 日均值、TVL 和无常损失字段派生，只作为研究提示。
- `数据源健康` 放在右侧诊断栏，使用中文数据集名、中文状态和提醒计数，便于判断哪些数据集完整、部分失败或为空。
- 面向操作者的可见文案优先使用中文；`DeFiLlama`、`24H` 等来源名或行业缩写可保留，但必须放在中文语义里。

## 数据来源

- Summary API: `GET /api/v2/onchain/summary`
- Source provider: DeFiLlama public API, no API key required for the first slice.
- Endpoints:
  - `https://api.llama.fi/v2/chains`
  - `https://api.llama.fi/protocols`
  - `https://api.llama.fi/overview/fees`
  - `https://stablecoins.llama.fi/stablecoins?includePrices=true`
  - `https://yields.llama.fi/pools`
- Backend normalizes snake_case summary fields and the frontend receives camelCase through the shared API client.
- Backend keeps a short in-memory TTL cache for same-process navigation and a 30-minute real summary snapshot at `data/cache/onchain_summary.json`, so backend restarts or repeated page opens can render from the latest stored DeFiLlama-backed summary before calling upstream again.
- 稳定币收益池会过滤到有有效锁仓量且年化收益有上限的数据；这些只是研究线索，不是推荐。

## 交互规则

- `刷新` reloads `/api/v2/onchain/summary`.
- Segment buttons switch between overview, protocol research, and yield opportunity tables without triggering mutations.
- 协议研究支持本地搜索、类别筛选、链筛选，以及按锁仓量、费用/TVL、7 日变化排序；这些筛选只作用于前端已返回行。
- 收益机会支持链筛选、风险筛选，以及按年化收益、池锁仓量、风险优先排序；这些筛选只作用于前端已返回行。
- 星标观察清单是本页本地状态，来源只能是当前 summary 中真实存在的链、协议或收益池行。它不持久化、不调用写接口、不影响策略或账户。
- `链上术语` 使用工具条内的紧凑 tooltip 解释 `TVL`、`APY`、`无常损失` 和 `费用/TVL`，避免把页面变成教学长文或空白说明卡。
- Tables use internal scrolling for long lists so the page shell remains stable on wide and narrow screens.
- Guest sessions may view the page because it only uses read-only v2 GET endpoints.

## 空态和错误态

- If every DeFiLlama endpoint fails or returns no rows, API status is `waiting_for_data`, arrays are empty, and `empty_reason` is `等待 DeFiLlama 返回真实链上数据`.
- If only some endpoints fail, API status is `partial`, successful datasets remain visible, and warnings identify the failed source groups.
- 前端在右侧诊断栏的 amber 提示面板中展示 warnings，并把已知 DeFiLlama 数据集 key 翻译为中文名称。
- Every table supports empty arrays with a stable empty panel.
- The page must not render fabricated protocol, chain, fee, stablecoin, or yield rows.
