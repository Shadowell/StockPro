# 套利中心页面设计

## 路由与归属

- Route: `/arbitrage` 直接访问；不作为侧边栏独立菜单页面展示
- Frontend owner: `frontend/src/pages/ArbitrageCenter.tsx`
- Backend owner: `backend/app/api/v2/endpoints/arbitrage.py`
- Contract: `docs/contracts/跨所套利.md`

## 页面目的

套利中心是跨交易所套利研究的直接路由工作台。第一版聚焦 OKX 与 Binance USD-M 永续之间的只读研究视图，展示机会列表、价差矩阵、资金费率排行、净优势计算器、组合持仓、腿状态、净敞口、预估收益和实际收益。它不作为侧边栏独立菜单页面；日常资金费率列表放在首页 `榜单列表` 的 `费率榜` 中。它不提供真实跨所下单、划转、借币、提币或自动实盘套利操作。

## 首屏布局

- 顶部标题使用 `套利中心`，右侧提供刷新按钮。
- 顶部 KPI 使用三张紧凑卡片展示 `净敞口`、`预估收益`、`实际收益`。
- 交易所接入状态展示 OKX 与 Binance USD-M 的配置状态；只有 API Key 但没有 Secret 的 Binance 账户显示为 `仅展示`。
- `净优势计算器` 位于接入状态下方，提供 OKX/Binance bid/ask、资金费 bps、名义金额、滑点和 maker/taker 费率模式输入；默认使用市价单 taker 费率。
- 主工作区由 `机会列表`、`资金费率排行`、`价差矩阵`、`组合持仓` 和 `腿状态` 组成。
- 页面使用全宽工作台布局，不使用营销 hero、说明型大卡片或截图专用假数据。

## 数据来源

- Summary API: `GET /api/v2/arbitrage/summary`
- Summary API 读取 OKX public ticker/funding、Binance USD-M public 24h ticker、premium index 与当前 order book depth；不需要 Binance Secret，也不读取真实账户权益、持仓或订单。
- Summary API 同时合并运行中跨所 paper 策略注册到 `CrossExchangePaperPortfolioRegistry` 的组合快照，用于展示 paper-only 组合持仓、双腿状态、净敞口和实际收益。
- 当 OKX 与 Binance USD-M 存在共同 Top30 永续标的、双方资金费率与盘口深度可用时，summary 会生成真实 `机会列表`、`资金费率排行` 和 `价差矩阵`；机会按扣除手续费、滑点和盘口深度过滤后的 `net_edge_bps` 降序展示。
- 费用默认值按交易所合约实盘费率近似：OKX SWAP maker/taker 为 `2/5 bps`，Binance USD-M SWAP maker/taker 为 `1.8/4.5 bps`。当前市价单和 Backtrader 市价撮合都按 taker 计费；净优势计算器的 `总成本` 默认包含双腿开仓和双腿平仓手续费，再叠加手工输入滑点。
- Binance 默认账户展示来自服务端环境变量 `BINANCE_API_KEY` / `BINANCE_API_SECRET`，前端只接收 masked key 和状态。
- 组合持仓和腿状态来自跨所 paper portfolio；没有运行中的跨所 paper 策略或没有成交组合时显示稳定空状态。回测记录的组合腿展示仍属于后续范围。

## 交互规则

- `刷新` 重新请求 `/api/v2/arbitrage/summary`。
- 净优势计算器本地实时计算两种方向：`Binance 多 / OKX 空` 与 `OKX 多 / Binance 空`，输出建议方向、价差优势、资金费优势、总成本、净优势和按名义金额折算的预估收益；净优势不为正时显示 `不开仓`。
- 空状态会说明缺少双交易所公开行情、资金费率、盘口深度，或当前净优势未覆盖成本。
- 页面当前不提供启动、暂停、停止或真实交易按钮。

## 空态和错误态

- 没有双交易所数据时，各模块保留稳定空状态，不渲染伪机会行。
- 有真实 summary 数据时，`资金费率排行`、`价差矩阵`、`组合持仓` 和 `腿状态` 必须渲染表格行，不能用空 `<div />` 占位。
- API 失败时在页面顶部显示错误条，既不清空导航，也不跳转其他页面。
- 机会列表、价差矩阵、资金费率排行、组合持仓和腿状态都必须支持空数组。
