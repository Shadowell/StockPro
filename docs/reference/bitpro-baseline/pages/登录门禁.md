# 登录门禁页面设计

## 页面目的

登录门禁在 `BITPRO_AUTH_ENABLED=1` 时保护 BitPro，同时保留轻量演示流程。它支持管理员账号密码登录、临时访客邀请码登录，以及管理员设置面板中的访客邀请码和 MCP Agent Token 管理；不使用短信、邮箱验证、浏览器本地 JWT 或自助注册。

## 路由

- 登录没有独立公开路由。`AuthProvider` 启动时检查 `/api/v2/auth/me`；当 auth 开启且没有有效 session 时，渲染 `Login` 而不是 `MainLayout`。
- 访客深链可以带 hash 邀请，例如 `/#invite=BP-...` 或 `/#guest_code=BP-...`。登录页只读取 `window.location.hash`，自动选择访客模式，通过 `/api/v2/auth/guest/login` 提交邀请码，然后用 `history.replaceState` 清理地址栏 hash。
- 登录成功后回到 BitPro 主 shell，并把 session 保存在服务端 `auth_sessions` 行和 HttpOnly cookie 中。管理员登录默认跨浏览器重启保持，直到操作者点击退出或服务器 session 被撤销。
- 如果 auth 关闭，应用直接以本地管理员兼容身份渲染主 shell。

## 首屏布局

- Full-screen dark financial workspace.
- Desktop: left informational rail with BitPro identity and two compact permission summaries; right side contains the login form.
- Mobile/narrow: form remains the primary first-screen element.
- The form has a segmented control with `管理员登录` first and `访客邀请码` second; the default selected tab is `管理员登录`。带邀请码 hash 的访客深链仍会自动切到 `访客邀请码` 并自动提交。

## 交互规则

- Guest mode accepts a temporary code such as `BP-...` and submits to `POST /api/v2/auth/guest/login`.
- Guest hash-link mode accepts `/#invite=BP-...` and `/#guest_code=BP-...`; query-string invites such as `?invite=...` are intentionally not supported so the code is not sent as a normal HTTP query.
- Admin mode pre-fills the current deployment's administrator username `Shadowell`, accepts the password, and submits to `POST /api/v2/auth/admin/login`.
- Errors from the backend are shown inline in the form.
- Logout is available from the sidebar when auth is enabled.
- Guest-code sessions expire with the source code, have no separate click-time hours cap, and cannot use the administrator long-lived login behavior.

## 权限驱动界面

- Guests see the same first-level product pages in the sidebar as administrators, including 实盘、盯盘、监控、数据 and AI研发.
- Guests can read page data outside Settings configuration, but backend auth rejects `/api/v2/settings/*`, live trading operations, position close, strategy pause/start/stop, sync writes, signal writes, AI mutations, and trading order/transfer/cancel calls.
- Guest sessions show a sticky top notice inside the main shell: `访客模式：部分页面功能不可用，仅支持查看和受限回测；策略启停、实盘控制、配置修改、数据/AI 写入需管理员权限。`
- Administrators see the full sidebar and can open Settings.
- Settings 只向管理员显示，并使用 `设置中心` 双栏结构：左侧为 `AI 与模型`、`Agent 接入`、`访问权限`、`通知通道`、`显示偏好` 分组导航，右侧渲染当前分组的小配置块。新增大模型 Provider、API Key、Agent 接入或通知通道时，应新增独立配置块，不继续堆叠到已有表单。
- `AI 与模型` 分组包含当前模型路由、模型选择、模型新增、候选模型删除、保存与连接测试，以及 `模型厂商` 管理块。候选管理列表允许删除当前路由下的自定义模型，并可隐藏 DashScope 内置/免费候选；当前启用模型和默认模型不可删除，避免全局大模型配置失去兜底。管理员可以新增或更新 OpenAI、Anthropic、Google Gemini 或其他 OpenAI Chat Completions 兼容 Provider，填写厂商标识、厂商名称、API Key 环境变量、Base URL、默认模型和模型候选列表；服务端只持久化这些元数据，不保存 API Key 明文。内置 `Grok` 通过 `PUT /api/v2/settings/llm-provider` 也可作为全局 HTTP 路由，使用服务端 `XAI_API_KEY` 和固定 xAI endpoint；禁止同名历史配置覆盖其传输或凭据身份。点击 `启用厂商` 会调用 `/api/v2/settings/llm-provider` 切换全局运行时路由，后端在切换前检查该 Provider 的环境变量是否已配置；legacy/兼容消费者保留 `get_qwen_client`，而 Planner、Strategist、Evaluator 的任务级研究执行使用 `get_research_provider_client` 并复用已 pin 的 Provider、模型和能力快照。
- `模型厂商` 使用 Provider 能力卡片合并 `/api/v2/settings/llm-model` 的配置元数据与 `provider_capabilities`；卡片的 Provider 身份和 `transport_type` 以服务端能力注册表为准，历史配置行只补充安全的 HTTP `Base URL`、环境变量名等元数据。内置 `Codex Provider`（`Codex CLI`）、`Cursor Provider`（`Cursor CLI`）和 `Grok` 即使没有独立配置行也必须可见，并展示真实的托管登录/命令状态、配置/声明模型列表和健康状态；CLI 能力同时区分 `command_available` 与 `login_verified`，命令存在但固定的 `codex login status` / `agent status` 探测未通过时显示“登录未验证”，不能把“命令可用”当成已配置，任务 pin 也必须拒绝该状态。服务端异步合并同一 Provider 的并发探测并在 TTL 内复用结果；只接受明确登录成功且不含未登录标记的状态，任何 stdout/stderr、账号或 token 均不得回传。Codex 的 models 是注册表声明列表，不等于 CLI 探测；Cursor 的实际模型列表只有显式调用 `agent --list-models` 成功后才标记为已探测，未探测/失败不补造模型。浏览器不能创建任意 CLI Provider 或提交命令路径。
- 当前设置中心不会自动执行 Cursor `agent --list-models`；静态能力列表统一标记为“已声明/当前配置模型”，只有服务端提供真实 `probed_at`/probe status 时才可标记为“已探测”，否则不作探测成功声明。
- 卡片展示模型、思考深度、速度模式、工具调用、结构化输出和恢复能力，只渲染服务端实际返回的候选；能力数组为空时显示“不支持”，不补造选项。HTTP Provider 的新增表单仅接受 Base URL、API Key 环境变量名、默认模型和模型候选，绝不接收或保存 API Key 明文；CLI Provider 由内置适配器管理，不要求 HTTP 凭据，运行在只读隔离目录。DashScope 任务的 `reasoning_effort=auto` 继续映射现有 `AI_AGENT_ENABLE_THINKING` 与 `AI_AGENT_THINKING_BUDGET`，能力快照明确声明该兼容模式。`刷新能力` 只刷新能力配置，只有连接测试成功才在当前卡片显示“刚刚测试通过”。健康状态分为“健康”“不可用”和“未探测”三态：未配置与未探测不冒充服务错误，明确后端 `error_code` 才显示不可用。
- Provider 的编辑、连接测试、启用/停用都使用服务端真实响应；错误可为 detail 字符串或 `{code, error_code, message}` 结构，前端统一解析并脱敏后展示。HTTP 连接测试的总 deadline 覆盖连接、headers、完整响应、解析与重试等待，超时或输出超限后必须关闭响应且不得切换 Provider。当前全局 Provider 或运行中 AgentTask 引用的 Provider 由后端拒绝停用，卡片保留后端错误原文/错误码的可读信息；Provider 路由禁止静默切换，失败必须停在明确错误态。卡片请求在关闭设置中心、切换 Provider 或产生新请求时取消/忽略旧响应，避免过期能力和测试结果覆盖当前状态。
- AgentTask 的 Provider/模型/深度/速度和脱敏能力快照继续由 AI Lab 独立持久化。FactorLab **阶段 2/3 MVP** 同样从设置中心读取真实 Provider 能力，但在自己的 research-task/experiment 台账固定选择；启动默认注册十六个内置定义和默认实例（包含 Volume Z-Score、MFI、量价相关性、OBV、VWAP），summary/catalog 读取所有已注册定义与实例（包含后续自定义定义）。FactorLab Provider 只提交严格组合 JSON，不连接现有 BitPro MCP，不获得 Paper/Live mutation；独立 `factorlab_research` gateway 未实现，逐工具授权仍是后续范围。
- 设置中心和新增 Provider 表单均使用 `role="dialog"`、`aria-modal` 和标题关联；设置中心打开时将焦点放入关闭按钮并在 Tab 范围内循环，关闭后回收至打开按钮。嵌套新增 Provider 表单单独管理焦点入口、焦点陷阱和回收；Escape 先关闭嵌套表单并阻止事件继续关闭外层设置。动态探测/保存状态使用 `role="status"`，错误使用 `role="alert"`，健康状态同时提供图标和文字。
- `访问权限` 分组显示 `访客邀请码管理`。生成表单把每个字段标签和输入框放在同一个响应式网格单元里，确保桌面和移动端都保持对齐；管理列表只显示有效邀请码，删除行会撤销该邀请码并从可见列表移除，同时保留后端审计历史。
- `Agent 接入` 分组显示 `MCP Agent Token`。模块展示已配置/未配置状态、脱敏 token 列表、scope、有效期、最近使用时间、`BITPRO_MCP_API_TOKEN`、当前认证 header 和远程 MCP 路径。`生成 Token` 通过 `POST /api/v2/settings/mcp-agent-tokens` 创建默认 `R/W/L` 的 `bp_mcp_` token；明文只在当前响应面板出现一次并提供复制操作，服务端只在 `mcp_agent_tokens` 保存哈希、前缀、scope、tool group、限流、过期和最近使用时间。旧 `POST /api/v2/settings/mcp-token/generate` 仍保留给单 token 自动化，并同步写入 `app_settings.mcp_api_token` hash 快照。
- `通知通道` 分组包含飞书 Webhook，并预留 Telegram、Email、Slack 等通道扩展槽。
- 生成的 MCP token 同时认证远程 `streamable-http` MCP 和本地 `stdio` MCP client 对受保护 `/api/v2` 路由的调用。当 `BITPRO_AUTH_ENABLED=1` 时，有效 token 请求被视为 admin 级 Agent 调用，不再返回 `401 请先登录`。

## 空态和错误态

- Loading: full-screen `正在检查登录态…`.
- Missing or expired session: login page remains visible and shows a clear expired/revoked message when `/auth/me` reports unauthenticated after a previous session.
- Invalid credentials or guest code: inline error; no main layout is rendered.
