# 因子库页面设计

## 路由

- Route: `/factorlab`
- Frontend owner: `frontend/src/pages/FactorLab.tsx`
- Backend owner: `backend/app/api/v2/endpoints/factorlab.py`
- Contract: `docs/contracts/factorlab-workbench.md`

## 页面目的

`因子` 是 FactorLab 的因子目录与机器学习验证工作台。操作者可以审查连续因子和不可变实例，也可以选择市场、真实历史标的、周期、日期、手动/自动/混合组合、Provider、模型、思考深度、速度和研究预算，启动可暂停/显式恢复的研究任务。研究结果只形成不可交易候选，不直接进入策略、Paper 或 Live。

当前交付为 **阶段 2/3 MVP**，使用独立 research-task/experiment 台账。独立 `factorlab_research` gateway 未实现；Provider 不做 tool calling，只提交严格结构化组合。

## 首屏布局

- 使用全宽深色金融工作台布局，顶部由 `LibraryBig` 图标、`因子库与实验` 标题、`机器学习验证`、`研究候选` 状态和 `刷新` 按钮组成。
- 首行六个紧凑 KPI 展示 `定义总数`、`参数实例`、`研究任务`、`Trial`、`最新值` 和 `物化分区`，所有数值来自真实 API/SQLite/Parquet；任务和 Trial 是累计审计证据，归档不会减少累计数。
- `因子实验配置` 提供手动/自动/混合组合，市场、周期、日期、标的池、Provider、模型、思考深度、速度、因子勾选、手工权重、horizon、候选、时间和连续无提升预算。自动/混合模式首次打开默认选择 `Codex / gpt-5.6-sol / medium / standard`；如果当前能力列表不支持其中某项，则回退到该 Provider 的真实候选。手动/自动/混合模式和任务列表当前项使用全站统一黄色选中底色。
- `任务与 Trial` 左侧列出未归档任务和删除入口，右侧展示 dataset snapshot、cursor、停止原因、暂停/恢复，以及模型、Score、20bps、40bps、PF、回撤和拒绝原因。
- 主区左侧为 `因子定义` 表，展示名称/版本、家族/角色、默认参数、预热根数、方向语义、内核和实现哈希。
- 主区右侧为 `数据与运行边界`，明确目录、Parquet、研究指标、策略运行时和 Paper/Live 的真实接入状态。
- 下方 `已注册参数实例` 表展示稳定实例 ID、所属定义、规范化参数、所需 K 线和每行的默认/已注册状态。
- 桌面使用主表加右侧诊断栏；窄屏改为上下布局，表格保留内部横向滚动，不能压缩长实例 ID 或覆盖控件。

## 数据来源

- Summary API: `GET /api/v2/factorlab/summary`。
- Research API: `POST/GET /api/v2/factorlab/research/tasks`、`GET/DELETE /research/tasks/{task_id}`、`POST /pause`、`POST /resume`、`GET /trials`。
- 后端应用启动时遵循“启动默认注册十六个内置定义和默认实例”的幂等规则；summary/catalog 读取当前所有已注册定义与实例，包含后续自定义定义。默认内置十六个；目录读取全部已注册。
- 成交量家族包含 `volume.volume_zscore`、`volume.mfi`、`volume.price_volume_corr`、`volume.obv_slope` 和 `volume.vwap_distance_atr`；分别表达异常放量、资金流方向、量价确认/背离、OBV 趋势和 VWAP 偏离，全部作为连续特征进入相同 walk-forward/成本门禁。
- 定义、实例和最新值读取生产 SQLite 的 `factor_definitions`、`factor_instances`、`factor_latest`。
- 物化分区数来自 `data/factors/values/**/part-*.parquet` 的真实文件计数。
- 页面不得生成演示因子、模拟最新值或伪造物化分区。

## 交互规则

- `刷新` 读取 summary、研究任务和当前 trial，不触发策略配置或交易。
- `启动研究` 只创建 FactorLab 研究任务；auto/hybrid 使用所选且已验证的 Provider 生成结构化组合，manual/hybrid 的权重转换成安全 AST。
- `暂停` 在 SQLite 写入硬停止状态；不会自动恢复。`恢复` 由操作者显式触发并从 trial cursor 继续。
- `删除` 是软归档：任务从当前列表隐藏，但 task、dataset snapshot、Trial、模型产物清单和审计事件继续保留。`queued/running` 任务必须先暂停，不能直接删除。
- 后台最多并发 2 个研究 runner；预计输入超过 2,000,000 symbol-bar rows 时创建请求直接失败，不让大数据集挤占 API/Paper 资源。
- `ADX14 ≥ 18` 等条件在页面中明确标记为后续实验/策略参数，不属于因子定义。
- 页面不读取真实账户私有状态，不创建或修改策略/Paper，不接入 Live，不改变现有策略信号和退出保护。
- Provider 提案通过 `get_research_provider_client` 使用任务 pin；legacy/兼容调用继续保留 `get_qwen_client`。Provider 只接收脱敏因子目录和严格组合 Schema；不连接现有 BitPro MCP，不获得 Paper/Live 工具。独立 `factorlab_research` gateway/tool group 和逐工具授权仍未实现，因此当前 Provider 不做 tool calling。
- Guest 可查看目录；研究任务写操作继续由后端权限门禁控制。

## 空态和错误态

- 首次读取显示固定高度加载面板，侧边栏继续保留。
- API 失败时展示真实错误摘要，保留刷新入口。
- 定义或实例为空时分别显示稳定表格空态，不插入假行。
- `最新值` 和 `物化分区` 为 0 时直接显示 0。任务或 trial 为空时显示真实空态，不插入演示行。
