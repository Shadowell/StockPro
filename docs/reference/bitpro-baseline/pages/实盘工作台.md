# 实盘页面设计

## 路由

- 路径： `/live-real`
- 组件： `frontend/src/pages/liveTrading/index.tsx` with `modeScope="live"`
- 侧边栏标签/图标： `实盘` / `Rocket`

## 页面目的

实盘是受控的 OKX 与 Binance USD-M 实盘执行工作台。操作者先选择已复核的 source paper strategy，再分别对目标账户执行独立预检；该账户预检通过后，才可通过 `绑定并启用下单` 二次确认完成账户绑定和账户级实盘订阅创建。

## 首屏布局

- 顶部账户管理区把账户选择/新增入口与资产摘要分开承载，并默认折叠，让首屏优先展示策略选择和实盘订阅面板。
- 顶部账户选择器使用 OKX / Binance USD-M 并列 Tab，两个账户都已配置时直接显示两个入口，不使用下拉菜单；选中态为蓝色高对比底色，未选中项保持暗色。
- Middle strategy list shows source paper strategies eligible for live subscription and keeps their symbol identity aligned with `/live` cards through the shared fixed-size symbol icon.
- 右侧 `实盘面板` 在标题下方常驻展示 OKX / Binance USD-M 并列账户 Tab；它与顶部折叠账户管理区共用同一个当前账户状态，切换后面板的订阅状态数量、已部署数量、合约持仓、订单明细和订阅卡片必须同步刷新，不使用下拉菜单。
- Right live panel shows bound subscriptions, current positions, orders, and audit context.
- Risk style uses neutral surfaces with red only for explicit risk borders/text/badges.

## 数据来源

- `live_accounts`、账户绑定 API，以及 OKX / Binance USD-M 私有读取接口。
- `live_strategy_settings` and `live_strategy_subscriptions`.
- Source paper strategy runtime status APIs.
- `live_signal_executions` for order audit and error history.
- 首屏 `GET /api/v2/live/strategies` 使用单次批量快照读取策略、设置、账户绑定、账户和订阅；动态策略可部署性按策略内容版本缓存，列表组装在线程中执行，避免慢列表请求阻塞其他 API。

## 交互规则

- 左侧 `策略选择` 的 `全部` / `可部署` / `已部署` 只展示源模拟策略仍为 `status=running` 的条目；未运行、暂停、已停止策略不得出现在候选列表。`可部署` 再收紧为运行中、可解析且未加入工作台；`已部署` 只统计仍在运行且已加入工作台的策略。筛选数量与当前搜索词联动。
- 新增账户和启用账户都需要操作者明确输入或确认。账户表单支持选择 OKX 或 Binance USD-M：OKX 需要 API Key、Secret Key、Passphrase；Binance USD-M 需要 API Key、Secret Key，不显示或保存 Passphrase。保存前必须完成各交易所的读取与非成交 Trade 权限测试。
- `加入实盘` 只把策略加入工作台，不绑定账户、不预检、不创建订阅。每个可用账户行初始显示 `预检`；该账户预检通过后，新账户显示 `绑定并启用`，历史上已绑定但未部署的账户显示 `启用下单`，两者仍需真实资金二次确认。
- 独立预检只要求策略已经加入工作台，不要求目标账户提前绑定，也不得因为预检通过或失败创建账户绑定或订阅。预检结果以 `strategy_id + account_id` 隔离；OKX 的结果不能让 Binance 跳过预检，OKX 已启用也不能遮蔽 Binance 的预检入口。
- `POST /api/v2/live/strategies/{strategy_id}/enable-account` 在一个请求中先检查账户权限、持仓模式、交易规则、订单预检和策略止盈止损；全部通过后才写入绑定并创建 `running` 订阅。任一检查失败都不得为新账户留下绑定或订阅。
- 源模拟策略已有持仓不阻断新账户启用；新建订阅只消费创建后产生的标准化信号，不补发历史开仓信号。已存在的历史绑定不会因版本部署自动启用。
- 同一源模拟策略可同时绑定 OKX 与 Binance USD-M 账户。每个账户具有独立预检、订阅、执行与错误状态；一个账户拒单或网络失败不得暂停、停止或隐式撤销另一个账户的订阅。
- Binance USD-M 账户资产区展示合约钱包余额、持仓和订单审计；其余额仅有一个 `USD-M 合约账户 / Futures Wallet`，不得套用 OKX 的资金账户、现货资产语义。双向持仓优先以 Binance 原生 V2 `positionRisk` 读取并保留 `LONG` / `SHORT` 腿、逐仓/全仓和杠杆，不能因通用 CCXT 读取触发现货权限检查而显示为空。交易所未提供可复核的账户历史权益时，1日/7日/30日收益率显示 `--`，不生成估算或 mock 数字。
- 顶部 `实盘账户管理` 是可折叠区块，默认折叠；标题、图标、箭头和标题行空白区域都属于同一个展开/收起热区，展开后才显示账户 Tab、新增账户表单入口、资产读取状态和账户资产面板。账户 Tab 与 `增加账户` 是独立控件，点击它们不得误触折叠。折叠只影响展示密度，不停止后台账户快照刷新，也不改变账户绑定、预检或实盘部署规则。
- 切换顶部实盘账户时必须立即清空上一账户的资产、读取错误、只读提示和 loading 状态；命中当前账户的非空缓存或当前账户资产读取成功后，不得继续展示上一账户的缺少 Secret Key、零资产或读取失败提示。空资产缓存不得阻止当前账户私有接口读取；只有当前选中账户本身确实为空、不支持实盘资产读取或当前请求失败时，账户区才展示对应空态或错误。
- 中间 `实盘策略列表` 的策略卡提供受控 `移出` 操作。未部署或所有实盘订阅均已 `stopped` 时，操作者二次确认后可把该策略移出列表并保留历史实盘执行审计；若任一账户仍有 `running` / `active` / `deployed` / `paused` 实盘订阅，页面必须弹出提醒并要求先到右侧 `实盘面板` 停止订阅，后端也必须拒绝移出请求。
- 启用检查校验账户权限、持仓模式、合约规则、规模、非成交订单参数和止盈止损。最近检查结果可通过 `查看最近启用检查` 打开；显式关闭后，只有再次点击或产生新结果才重新打开。
- 当前退出保护来自策略内部 K 线/tick 平仓信号，不在 Binance/OKX 页面显示为交易所原生止盈止损条件单；页面不得把两者混为一谈。
- 右侧 `暂停实盘信号` / `继续实盘信号` / `停止` 只影响当前账户的实盘订阅，不暂停或停止源模拟策略；反向也要保护源策略，若源模拟策略仍有 `running` / `active` / `deployed` 实盘订阅，模拟盘 `/live` 的 `暂停交易` 和 `关闭交易` 会被后端拒绝，必须先在右侧 `实盘面板` 停止实盘订阅。
- Contract position actions (`平仓` / `市价全平`) must reuse the live broker's OKX direction logic: when OKX returns `posSide=net`, the page and close request resolve direction from explicit `side` first, then fall back to signed size only if the exchange omitted side.
- Right-panel pause/resume/stop controls follow the visible `live_strategy_subscriptions` row for the selected account; a subscription remains controllable even if its middle-list workspace binding was previously removed.
- 停止实盘订阅前必须先检查当前账户合约持仓。若存在该订阅相关非零持仓，确认弹窗列出标的；确认后先平掉匹配持仓再停止订阅，取消时持仓和订阅都保持不变。后端 `POST /api/v2/live/strategies/{strategy_id}/stop` 也必须独立执行同一持仓校验，仍有相关持仓或无法确认持仓为空时拒绝停止。

## 空态和错误态

- Missing live account permissions must block deployment with actionable errors.
- Empty live positions/orders should show a read-only empty state, not simulated rows.
