# 回测页面设计

## 路由

- 路径： `/backtest`
- 组件： `frontend/src/pages/Backtest.tsx`
- 侧边栏标签/图标： `回测` / `FlaskConical`

## 页面目的

回测是异步多实例回测工作台。它启动真实 K 线的 Backtrader 任务，把运行中任务与已落库结果合并成一张列表，并在详情页复盘路径、成交和绩效。

## 首屏布局

- Page shell uses the same full-width, left-aligned workspace container as market, monitor, data, watch, and simulation pages. It must not center the whole console inside a narrow `max-w-* mx-auto` wrapper, so external wide displays keep the backtest controls aligned near the sidebar.
- 页头遵循全站标准：`text-2xl` 加粗标题配 `h-6 w-6` 的 `FlaskConical` 图标，副标题一行灰色说明；主操作是蓝色实心 `创建回测`，打开分步向导；次操作是描边 `批量回测`，只为运行中的模拟策略批量建任务。可见文案保持短标签，完整名称保留在 `aria-label`（`创建回测实例` / `创建批量回测实例`）。
- Main list merges active/interrupted local instances and persisted `/backtest/results` rows.
- 列表页是「左筛选栏 + 密集表格」的研究工作台布局：桌面端左侧固定 208px 筛选栏（`状态` / `资产` / `周期` 三组竖向按钮组，带计数徽标，选中态黄色），右侧为列表卡片；`lg` 以下筛选栏折叠为三条横向滚动 chips。`周期` 筛选按当前加载实例的实际周期动态生成。
- 列表是密集表格行（`min-w-[1180px]` 内部横向滚动），列依次为：对比勾选、策略/标的（含资产徽标、`数据失信` 徽标、创建编号与运行进度条）、周期、区间、`收益`、`回撤`、`夏普`、`交易`、状态、创建时间、操作。策略名允许换行保持完整可见；年化、胜率和其他诊断指标只出现在详情页，避免同一数字在列表和报告里各讲一遍。
- 列头排序：`收益` / `回撤` / `创建时间` 列头可点击切换升降序（箭头指示，激活列黄色），默认 `创建时间 ↓`；`回撤` 默认低值在前，持久化历史排序仍由 API 在分页前完成。资产、状态、周期、周期模式、矩阵周期和标的切换的选中态统一使用黄色底色。
- **对比模式**：每行复选框最多勾选 4 条（2–4 条可发起），勾选后列表上方出现黄色操作条（`对比选中` / `清空`）。对比面板上半部分把各记录权益曲线归一化为累计收益百分比叠加（每条一个颜色、错峰绘制动画），下半部分为指标差异表（净收益、年化、回撤、夏普、胜率、盈亏比、交易数、手续费；最优值黄色高亮，回撤与手续费取最小值）。本地实例直接用已加载结果，历史记录逐条拉取 `/backtest/result/{id}` 补齐权益曲线。
- Row action buttons use one polished dark financial toolbar style. `详情` is blue, `日志` is neutral unless an error exists, destructive actions stay red, and completed rows use a brighter `成功` state with a check icon and success-specific emerald tone instead of sharing the generic green action style.
- Asset chips must stay accurate while strategy metadata is loading: contract rows can infer `合约` from the saved instance/result name such as `[合约]...`, instead of falling back to `现货`.
- Instance fuzzy search sits inside the `回测实例` list card header, immediately after the title/count, so operators search the list where the records are shown instead of in the upper filter toolbar.
- 动效合同：运行中实例进度条使用流光动画；表格行进入时按索引错峰淡入（`row-enter`）；判决带数值变化时滚动过渡。所有动画必须尊重系统 `prefers-reduced-motion: reduce`（直接呈现终态）。

## 数据来源

- `backtest_jobs` for queued/running/cancelled/interrupted jobs.
- 独立 Python 回测 worker 子进程执行 Backtrader 策略循环；FastAPI 进程只负责创建、等待、轮询和取消任务。
- Backtrader 的同步 `next()` 通过 `BTStrategyAdapter` 驱动策略异步生命周期；同一次回测复用一个事件循环，避免长窗口或高频回测为每根 K 线重复创建 loop/线程池。正常结束、策略异常和取消都会关闭该适配器资源。
- `POST /api/v2/backtest/run_running_strategies` for the running-strategy batch shortcut; it creates ordinary `backtest_jobs` and returns created jobs plus skipped running strategies.
- `backtest_results` for lightweight persisted result rows and `/backtest/result/{id}` for full persisted reports. 列表和详情都必须带上 `LEFT JOIN strategies` 得到的 `strategy_name`；控制台标题优先用当前策略库命中的名字，其次用这条持久化名称，不能因为策略不在 `/strategies` 第一页 60 条里就写成 `策略已不存在`。只有 `strategy_id` 在库里确实没有对应行时，才显示 `策略已不存在`。
- File K-line store 和真实交易所 fetch/cache fallback 提供历史 bars。同一 timestamp 同时存在文件 store 与旧 SQLite 行时，以文件 store 行为主；Backtrader 在策略运行前还会检查 OHLC 合法性和连续相邻 bar 异常跳变，使污染 K 线缓存显式失败，而不是生成看似成功的报告。
- BTC/USDT 1D real K-lines for benchmark return and strategy excess return.
- Strategy registry/config for symbols, market type, costs, and timeframe.

## 交互规则

- Create flow uses a staged modal wizard: fuzzy-search strategy selection, date/cost config, quick ranges, final confirmation.
- `创建批量回测实例` opens a shared dark confirmation dialog instead of the staged wizard. Confirming calls `/backtest/run_running_strategies`, which only considers `status=running` paper/simulation strategies, skips live/non-paper/unresolvable running rows, defaults to `100U`, uses one year ago through yesterday as the date range, and keeps `策略定义` as the period mode. The backend also preflights local real K-line coverage for the resolved symbols/timeframe; strategies with known insufficient coverage are returned in `skipped` with a sync-or-shorter-range reason instead of becoming failed instance cards. Returned jobs are inserted into the same local instance list with `activeJobId`, so existing polling, cancel/resume handling, result hydration, history refresh, and card actions continue to apply. The backend schedules those returned jobs independently with bounded concurrency, so a slow 1m strategy does not serialize the entire batch behind it.
- The strategy selector is a searchable combobox, not a native dropdown. It filters backtestable paper/research strategies by strategy name, symbol/range, asset type, and K-line timeframe, then shows matching rows with asset badge, canonical name, period, and scope.
- Parameter step includes a `周期模式` control:
  - `策略定义` uses the selected strategy's configured timeframe.
  - `指定周期` runs once on one selected K-line period.
  - `多周期矩阵` runs the same strategy/date/cost inputs across multiple selected periods and shows both period tabs and a comparison table in results.
- Period buttons use compact labels `1M / 5M / 15M / 30M / 1H / 4H / 1D`; all visible fallback period labels in instance rows, report metadata, strategy-definition mode, and matrix tabs must use the same uppercase style even when persisted/API values remain lowercase such as `1h`. The selected period must also drive the K-line review chart and the backend strategy config. Instance cards must show the effective period; matrix backtests show every selected period as separate chips.
- Stop/cancel and resume actions call backend job endpoints. Cancel writes the job to `cancelling`, so an isolated worker subprocess can stop even though it cannot share the API process's in-memory cancel set.
- 详情页只保留一个策略标题。详情页头与策略中心详情页同构：左侧是紧凑方形返回按钮，资产/状态徽标位于标题上方，标题使用 `text-2xl` 并允许换行；页头同时承载 `回测时间范围`、交易池/周期和 `数据可信度`，不再单独做一层只重复日期的报告壳，也不渲染 `回测研究报告` 徽标或 `单页报告 / K线复盘 / 绩效诊断 / 交易流水` 导航芯片，更不能拆成 `概要` / `绩效` / `交易记录` Tab。
- 指标合同是「一指标一处」：列表只比较 `收益` / `回撤` / `夏普` / `交易`；详情判决带只放 `净收益` / `超额收益` / `最大回撤` / `夏普`，数值使用全站 KPI 卡的 `text-2xl font-bold tabular-nums` 排版；`绩效明细` 只放判决带没有的拆解项，模块壳与 `研究诊断与审计` 同构（`bg-crypto-card/80` 卡 + 标题行 + 分隔线正文），三列面板复用同一套左侧色条语言（收益蓝、风险琥珀、交易翠绿），内部为紧凑指标行而不是 18 张等高大卡：`收益`（年化、期末权益、BTC/USDT 同期、手续费）、`风险`（Calmar、Sortino、年化波动、Beta、回撤持续）、`交易`（胜率、盈亏比、赔率、期望/笔、盈利/亏损、交易数）。`平均盈利`、`平均亏损`、`最大连胜/连亏`、`回测天数`、`K线样本`、`盈利/月亏` 和 `执行耗时` 不进判决带或明细表。每个数字旁保留问号 `HelpCircle` 公式说明，模块头不得再放重复的 `指标说明`。
- 报告正文顺序是：判决带 → `权益曲线` → `买卖点 K线复盘` → `绩效明细` → `研究诊断与审计` → 可选 `月度收益分布` → 可选 `交易分析` → `交易流水`。报告各模块统一使用 `rounded-xl border border-crypto-border bg-crypto-card(/80)` 壳与 `p-4` 内边距；月度收益格子的涨跌底色必须走语义 `bg-up` / `bg-down` 工具类，跟随全站红涨绿跌配置，不得硬编码红绿边框。审计区只写结论、闸门判断和成本，不再重复超额收益、Sortino、波动、Beta 或回撤持续的原始数字。
- `权益曲线` 使用懒加载的 `BacktestEquityCurve` 组件（echarts），只消费结果已落库的真实 `equityCurve` 与真实 BTC/USDT 1D 基准 K 线，不做合成或插值外推：主图是策略累计收益（%）与基准累计收益（%）双线（基准按日收盘 forward-fill 对齐到策略权益时间点，两条线都从 0% 起步），下方副图是回撤区间面积；支持 inside/slider 缩放与轴联动 tooltip，打开报告时曲线以约 1.1 秒回放式绘制。模块头不放收益/回撤数字（判决带已有），只放图例说明；`equityCurve` 少于 2 个点时整个模块不渲染。
- `交易分析` 使用懒加载的 `BacktestTradeAnalytics` 组件（echarts 三网格），放在交易流水之前，成交少于 3 笔时不渲染：左上是按成交时间累加的累计盈亏阶梯线；左下是单笔盈亏分布直方图（排除 0 盈亏的开仓腿，正负分色，观察盈亏尾部形态）；右下是交易原因分布横向条形（按笔数排序，tooltip 附该原因的累计盈亏）。平均盈利/平均亏损/最大单笔盈亏等成交结构数字只通过图表 tooltip 呈现，不进判决带或绩效明细表，保持「一指标一处」。
- 详情页 symbol scope 优先从结果自身策略元数据解析，只有缺少结果策略元数据时才回退到当前创建表单选中的策略，避免已持久化 ETH 结果继承 stale 选中策略交易池。Matrix backtest details expose a `周期详情` tab strip; switching it changes the single-page report's verdict strip, K-line review, compact metrics, monthly distribution, and trade table to that period's persisted result while keeping the comparison table visible. The trade ledger is a fixed-height dark frame with internal vertical/horizontal scrolling and a sticky table header, so long runs do not stretch the whole report page. The shared K-line review keeps EMA tooltip markers aligned with EMA line colors, formats EMA values to 5 decimal places, and renders B/S trade markers as short rectangular markers that show only the single `B` or `S` letter, match the candlestick body width, sit outside the candle high/low, and use same-color guide lines pointing to the exact execution-price K-line anchor. K 线复盘头部不再在右侧重复展示区间收益或区间最大回撤；多标的回测只用胶囊形 symbol chips 切换当前复盘标的。Markers outside the loaded K-line window are excluded from both rendering and y-axis range calculation. Benchmark comparison is always BTC/USDT close-to-close over the selected backtest date range, and `基准超额` is strategy cumulative return minus BTC/USDT benchmark return for the active period. Persisted history details should hydrate the same single-page report as freshly completed jobs; new records store the full result payload, while legacy records derive Calmar, fee drag, payoff, expectancy, and sparse equity-based volatility/Sortino only from stored summary/trade data.
- 如果生产审计脚本把旧结果标记为 `data_quality_status=invalidated`，实例列表必须显示 `数据失信` badge，详情页头显示红色 `数据可信度：数据失信`，并展示 `历史结果不可继续信任` 和审计说明。被标记的 completed 结果不应再作为可信结论继续展示给操作者。
- `研究结论`、`风险闸门` 和 `成本审计` 使用始终展开的 `研究诊断与审计` 模块，放在 K 线复盘和绩效明细之后。模块头左侧是标题/图标，右侧是三个小节 chip；不得做成手风琴或 chevron 折叠。桌面三列、窄屏堆叠，左侧色条区分小节。研究结论写状态、相对基准的跑赢/跑输判断、样本长度和数据可信度；风险闸门写回撤/Calmar/Sortino/样本的通过或偏弱判断，不回显已经出现过的原始数字；成本审计保留手续费占本金、单笔平均费用、交易频率和平均持仓。
- The trade table shows historical fill rows newest-first. Contract rows include `杠杆`, `保证金`, and `成交名义` in addition to historical fill price, quantity, realized PnL, fee, and reason. New persisted rows read these values from the Backtrader order log; older rows may show inferred notional and blank leverage/margin where the original fill did not store them.
- Persisted result list loading must stay lightweight and paginated. The console requests the first 20 `/backtest/results` rows, asks for one extra row to decide whether `加载更多回测记录` should be shown, and uses `offset` for subsequent pages. `收益率` / `回撤` / `胜率` / `创建时间` sort controls pass `sort_by` and `sort_dir` into the API so sorting is applied globally before pagination, not just within the loaded page. The instance-list search input is placed in the `回测实例` card header and passes `q` to `/backtest/results` so persisted history is fuzzy-filtered before pagination, while browser-local running/interrupted rows are filtered in memory by the same query across strategy name, symbol, date, status, and period. The first-screen list skips matrix summaries so it does not parse large matrix result blobs; full matrix equity curves, trade arrays, period summaries, and detailed reports are fetched only when opening `/backtest/result/{id}`.

## 空态和错误态

- No records should show a neutral empty list, not a fake placeholder strategy.
- Failed jobs expose logs through the log dialog.
- Missing K-lines fail explicitly with per-symbol detail.
- 如果 K 线缓存存在非法 OHLC 字段或连续相邻 bar 异常跳变，回测必须显式失败并提示清理重同步。文件 K 线写入路径也必须在落盘前校验批次，污染批次写入 `_quarantine/rejected-*.json` 而不是进入正常分区。
- Reloaded local completed rows without a saved result payload are hidden so operators open the persisted history row instead of an empty report shell.
