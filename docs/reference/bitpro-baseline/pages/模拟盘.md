# 模拟盘页面设计

## 路由

- 路径： `/live`
- 组件： `frontend/src/pages/liveTrading/index.tsx` with `modeScope="paper"`
- 侧边栏标签/图标： `模拟` / `Activity`

## 页面目的

模拟盘 is the paper strategy instance console. It manages running/stopped simulation instances, paper account metrics, positions, trades, events, logs, equity samples, contract paper liquidation events, and manual paper-only close actions.

## 首屏布局

- Header uses the simulation workspace title and create action.
- Header 下方提供 `优选策略 / 全部策略` 视图 Tab，优选 Tab 显示在前并默认选中；优选数量使用当前运行中/暂停的模拟策略集合计算。Filter row includes asset class, unlabeled strategy-type pills (`全部` / `CTA` / `马丁` / `AI` / `做市`), K-line timeframe, capital version, leverage, sorting, and fuzzy search.
- Cards show canonical strategy names, a green breathing light for running status, compact K-line timeframe, capital-version, and leverage pills such as `15M` / `100U` / `5X`, symbol scope with the shared symbol icon, profit amount plus return rate, Sharpe ratio, win rate, profit factor, and trade count. 卡片右上角提供星标收藏按钮，已收藏状态使用黄色实心星；点击只更新优选集合，不触发详情、暂停、关闭或任何交易行为。The card grid uses four columns on desktop-width and wide workspaces, with mobile fallbacks below that; search-filtered single results keep normal card width instead of stretching across the row. Primary and secondary metric numerals must not be truncated with ellipses, so KPI numbers remain fully visible at the fixed four-column density.
- Running paper strategy cards expose compact bottom-right trading controls: `暂停交易` / `继续交易` toggles the strategy engine state, while `关闭交易` stops the paper strategy without clearing persisted metrics. A paused strategy remains visible and can be resumed; a stopped strategy must persist `status=stopped`, keep the current `run_started_at` and the same open paper instance, disappear from the running/paused card list, and must not be restored by backend deploy or service restart. The next operator start or same-config `/live/configure` must reuse that instance and restore equity, trades, positions, and uptime; only `clear_metrics=true` or a real config/script change may close the session and start a new instance.
- 若同一源模拟策略存在 `running` / `active` / `deployed` 的实盘订阅，`暂停交易` 和 `关闭交易` 必须由后端拒绝，并提示操作者先到 `/live-real` 右侧 `实盘面板` 停止实盘订阅；前端卡片和详情页弹窗展示后端返回的明确原因，避免通过模拟盘掐断运行中的实盘信号源。
- `暂停交易` / `关闭交易` / `详情` render as one centered, adaptive full-width action group: narrow cards may stack the controls, while normal card widths distribute them as three equal columns with matching height, icon treatment, and width rhythm. `详情` stays last so card headers remain focused on identity and status.
- 控制台与实例详情共用全宽页面壳，内容随侧边栏右侧的可用视口宽度铺满，仅保留统一的 `p-6` 页面内边距；超宽屏不得用固定 `max-width` 截断详情内容并在右侧留下大块空白。
- 详情页标题栏展示实例运行状态和实例 ID；当前路由已明确属于模拟盘，因此不重复展示黄色 `模拟盘` 徽标。若共用组件进入真实实盘模式，仍保留红色 `实盘` 安全提示。策略说明区统一使用 `核心标的与交易逻辑`，避免用仅适用于股票的“选股”描述币、现货、永续合约或商品。详情页包含 KPI 卡片、可独立折叠的买卖点 K 线复盘、收益曲线与风控状态卡片，以及持仓、成交、事件、诊断和策略逻辑摘要。一级卡片标题统一沿用 `核心标的与交易逻辑` 的 `text-base` 字号，包括策略参数配置、策略运行诊断日志、动态标的池、当前持仓、成交与事件、买卖点 K 线复盘、收益曲线和风控状态；状态徽标、说明文字和卡片内部二级标题保持原有紧凑字号。`收益曲线` 默认选择收益率指标，折线使用红色 `#FF1744`，面积填充使用同色低透明度渐变。`风控状态` 默认展开，切换实例时恢复展开；标题整行作为折叠热区，收起后仍显示当前 `正常 / 已触发` 摘要和尾部箭头。持仓与成交的标的单元格展示共享标的图标，并保留行情预览和模拟平仓操作。运行中详情 KPI 行展示 `账户总额`、`总盈亏`、`收益率`、`夏普`、`胜率`、`盈亏比`、`交易次数`、`30日最大回撤`、`运行时间`；`30日最大回撤` 以当前时点为终点，只统计向前 30 个自然日内的权益峰谷并随时间滚动，允许旧回撤离开窗口后下降；后端按时间范围读取全部窗口采样，不使用固定点数近似。`夏普` 使用后端详情性能指标，控制台卡片已展示时不得在详情中省略。
- The create wizard's strategy-selection step has a local fuzzy search over creatable stopped strategies, matching strategy name, symbol scope, K-line period, type, capital version, description, and config metadata.
- The create wizard's run-parameters step defaults paper `模拟初始资金 (USDT)` to `100`; when the selected strategy defines `initial_capital`, the field syncs to that strategy value. The `通用启动风控` sliders are generic startup defaults/manual controls, not strategy-parsed parameters; strategy-derived parameters remain in the left-side strategy-definition panel.

## 数据来源

- Strategy instance/status APIs.
- 卡片指标来自批量运行策略状态：后端一次性读取所有运行策略最近 400 个持久化权益采样计算夏普，并另按精确 30 日时间范围批量计算 `30日最大回撤`；卡片不能因某个策略未打开过详情而显示 `--`。
- `/live/dashboard` for detail view.
- `strategy_trades`, `strategy_events`, and `strategy_equity_samples` persisted broker/runtime state.
- 收益曲线的胜率与盈亏比按每个采样时刻之前、本轮已持久化的退出成交累计计算；服务重启后不得退化为只读取内存成交。没有退出成交时胜率为空，没有亏损退出成交时盈亏比为空并展示无数据状态，不得绘制虚假的 `0` 线；历史错误 `0` 采样由接口按持久化成交即时重建。
- Real market K-lines for B/S review.
- Contract paper liquidation trades/events persisted by `ContractPaperBroker`; Feishu liquidation alerts use the unified saved Feishu webhook when configured.

## 交互规则

- Strategy-type filter resets K-line, capital, and leverage filters to `全部`; K-line filter resets capital and leverage to `全部`; capital filter resets leverage to `全部` so counts and visible rows stay consistent. `AI` uses the instance's AI-autonomous marker or canonical `[AI]` strategy-type tag; `做市` uses canonical `[做市]` names, `config.strategy_type=market_making`, or market-making strategy keys; `CTA` and `马丁` continue to use strategy naming/config semantics.
- `优选策略` 视图展示当前运行中/暂停且“手动收藏，或当前收益率严格大于 `5%` 且未被操作者排除”的模拟策略，并继续复用资产类型、策略类型、K 线、资金、杠杆、搜索和排序。收藏以稳定实例 ID 写入浏览器 `localStorage`，刷新页面后保留；策略暂时停止后收藏键仍保留，恢复运行时重新出现在优选视图。自动优选由卡片当前 `totalReturnPct` 实时派生，收益率刷新后动态进入或退出；`5.00%` 不自动进入，手动收藏可在收益回落后继续保留。自动命中时卡片显示黄色实心星，点击可取消该实例的自动优选并持久化排除选择；取消后显示空星，再次点击可恢复自动优选。优选为空时同时说明自动阈值和手动星标入口。
- Sorting defaults to `收益率 ↓`; controls are ordered `收益率`、`夏普`、`胜率`、`盈亏比`、`创建时间`, and only the active sort field appears selected.
- 首屏按 `/strategies` 的服务端分页连续读取全部策略页，再构建运行中/暂停的模拟实例并在完整集合上执行收益率、夏普、胜率、盈亏比或创建时间排序；页面不展示独立分页控件，因此不得只读取第一页 60 条后在残缺集合上本地排序。后续通过较慢、非重叠的后台任务刷新；卡片总盈亏、收益率、夏普、胜率、盈亏比和交易次数走独立批量指标路径，不得每几秒轮询 `/strategies`，也不得逐卡请求 `/live/dashboard`。夏普使用最近最多 400 个有效权益点的相邻收益率计算；少于 3 个有效权益点或收益波动为零时与详情页一致显示 `0.00`。
- Card-level trading controls use the shared confirmation dialog before pausing, resuming, or stopping a paper strategy.
- Guest sessions can view the simulation dashboard and details but run in read-only mode: create, pause/resume, stop, delete, clear, and paper position close controls are hidden or disabled. The backend still rejects paper mutations for guests.
- Detail B/S K-line review and account curve cards are expanded by default; clicking anywhere on either card header collapses or expands that card. The K-line review header shows the selected review symbol and the strategy-defined period as compact tokens, with the period rendered as an uppercase segmented-control token (`1H`, `15M`) using the same visual language as the account-curve range selector. The shared K-line review keeps EMA tooltip markers aligned with EMA line colors and formats EMA values to 5 decimal places.
- The B/S K-line review fetch is keyed by selected symbol, exchange, strategy timeframe, and the stable trade-marker timestamp set. Routine detail polling that returns the same trades must update markers without forcing the chart back into a loading state. B/S markers are plotted at the persisted execution price from `strategy_trades`; the marker is a short rectangle that shows only the single `B` or `S` letter, matches the candlestick body width, sits outside the candle high/low so it does not cover the K-line, and draws a same-color guide line to the exact execution-price K-line anchor, with a high-contrast border/shadow so the letter remains readable on dense candles. Markers outside the loaded K-line window are not rendered and must not contribute execution prices to the chart y-axis range. The action token stays available in the tooltip instead of being rendered inside the marker. The review symbol list prefers current paper positions and actual `strategy_trades` symbols; strategy config symbols are only a fallback when no runtime position or fill symbol exists, so heartbeat/default symbols do not appear beside unrelated real positions. The account curve defaults to the `1D` range. The detail route preloads the shared `WatchKlineChart` chunk, and bounded review-window K-line requests should return a sufficiently populated cached window without waiting for an OKX refresh.
- Detail `成交明细` refresh accepts persisted trade responses as either a bare array or wrapped `data` / `trades` / `items` / `results` payloads. When the dashboard still reports persisted trades, a transient empty, malformed, or failed trade refresh must preserve the current rows instead of showing `成交明细 (0)`.
- Current-position rows expose a compact front-of-symbol market button. Hover/focus opens a temporary `15M` preview, and clicking pins a closeable mini candlestick K-line panel so the operator can inspect the position symbol without leaving the detail page. The request still uses backend timeframe value `15m`; only the visible granularity label is uppercase. The preview fetch uses an explicit in-flight guard instead of relying on React state-updater side effects, so the panel cannot stay on a skeleton screen without sending the K-line request.
- Manual position close is paper-only and must never call real account endpoints. If the target paper position is already gone because a previous close succeeded or polling is stale, the close API treats it as a stale no-op success and the detail view refreshes the latest paper positions instead of showing a generic HTTP 400 failure.
- Contract paper positions can be automatically liquidated when isolated position equity falls below maintenance margin. The detail view must show the resulting liquidation trade/event, but the operator-facing trade direction displays the Chinese label `爆仓` in deep red instead of raw `liquidation_long` / `liquidation_short` enum text; the runtime pauses the paper strategy and emits a red Feishu alert if `paper_liquidation_alert` delivery is available.
- Detail KPI `账户总额` displays current paper equity as `$`-prefixed money with two decimals; it is `initial capital + realized/unrealized paper PnL` rather than the unmodified initial capital.
- 动态标的池面板：当 `/live/dashboard` 返回非空 `dynamic_pool` 字段时，详情页在 `当前持仓` 卡片上方渲染同一个可折叠的 `动态标的池` 组件。策略仍可在运行时持久化各自的 `_dynamic_pool_view` 原始结构；dashboard 读取边界把旧动量池、1H 因子池及后续动态池适配为 `schema_version=4` 的统一展示合同，固定包含摘要、时间、计数、候选、成员、持仓和事件。页面不得读取 `mode`、动量阈值、综合分字段或事件枚举来判断策略类型，只遍历后端提供的 `primary_metric`、`badges`、`metrics`、`label/message/tone`，因此新增动态池策略不再增加页面模式分支。三列统一为 `候选标的 / 池内成员 / 池内持仓`，列表固定最大高度（`max-h-80`）、超出部分纵向滚动；下方 `池事件流` 按时间倒序展示最多 200 条已本地化事件，固定约 8 条可视高度、超出部分滚动。每条事件固定为单行，顺序为完整日期时间、事件标签、日志信息；长内容不换行并允许横向查看。首次启用事件账本只建立当前候选/成员基线，不补写或伪造修复前历史事件；后续事件使用稳定 `event_id` 去重并随当前 Paper 会话持久化。数字变化使用 NumberFlow 滚动，卡片进出场使用 motion 弹簧动画并尊重系统减少动态效果设置。只有 `dynamic_pool=null` 的非动态池策略显示 `未启用` 徽标和空态；`status=warming` 显示通用预热态，停止的实例仍可展示最近一次持久化快照。本展示适配只读，不回写策略状态，不停止、配置、归档或新建 Paper 会话。策略运行诊断日志折叠框的箭头统一放在标题行尾部（与其他折叠卡片一致），不再使用行首箭头。
- 策略运行诊断日志：详情页每 10 秒轮询 `/live/events`，并继续合并 WebSocket 实时 `log/bar_diag`。后端读取时把内存诊断、当前持久化动态池事件和成交记录统一排序；动态池策略因此显示进入/退出候选、进入/退出趋势池、开仓和带退出原因/盈亏的平仓，普通策略也能从成交记录补显开平仓。动态池已记录的开平仓优先于同一笔成交日志，避免双份展示；服务重启不会让已经持久化的池事件或成交历史消失。每条普通日志和结构化诊断都采用单行时间流：完整日期时间固定放在最前面，随后显示日志级别/决策和日志信息；长内容在日志区域内横向滚动，不拆成上下两行。该日志面只读，不替代 `成交明细`，也不改变交易与 Paper 状态。

## 空态和错误态

- Empty filters show `未找到匹配的模拟实例。`
- Paused/stopped paper instances keep persisted metrics instead of showing zeroed account state.
