## 页面单元 01：产品定位、边界与阅读方式


![图01 - 首页行情总览](screenshots/01-home-overview.png)

*图01 - 首页行情总览。来源：生产路由 `/`，5120×2880 PNG。*
BitPro 是面向量化策略研究、回测、模拟盘运行、信号审计、监控告警和 AI 辅助研发的一体化工作台。普通使用流程不是“先下单”，而是先看行情和数据质量，选择或研发策略，再回测，随后以 paper/simulation 模式运行，最后根据监控、诊断日志和人工审核结果决定是否输出信号或进入明确确认的实盘试运行流程。

本文档按 61 个页面单元组织，每个单元都说明页面入口、主要模块、操作步骤和执行机制。截图来自生产地址普通浏览器导航，不使用 mock、不注入演示数据；涉及 Webhook、token、API Key、账户标识和实盘余额的区域已做轻度脱敏。

## 页面单元 02：全局导航与页面地图


![图01 - 首页行情总览](screenshots/01-home-overview.png)

*图01 - 首页行情总览。来源：生产路由 `/`，5120×2880 PNG。*
左侧导航是产品的主工作流骨架：`首页` 用于快速看行情与系统状态，`行情` 进入 K 线和订单簿，`数据` 管理 K 线缓存和同步任务，`策略` 管理策略定义，`回测` 做历史验证，`模拟盘` 启动 paper 实例，`监控` 汇总运行策略和告警，`复盘中心` 提供运行中策略的小时级复盘评分，`盯盘` 跟踪账户持仓标的行情，`链上研究` 提供 DeFiLlama 链上看板，`信号` 管理 OKX Signal Bot 通道，`实盘` 是显式确认后的 OKX Trade API 订阅执行工作台，`AI研发` 承接自主交易、策略研发和策略优化。侧边栏之外还有直达路由 `套利中心`（`/arbitrage`）、`因子库`（`/factorlab`）和 `自主研究`（`/arc`），以及全站登录门禁与设置中心。

建议按“数据 -> 策略 -> 回测 -> 模拟 -> 监控/复盘 -> 信号 -> 实盘预检”的顺序使用。直接跳到后置页面虽然可行，但缺少数据覆盖、策略逻辑、风控参数和模拟结果的上下文，容易误判页面指标。

## 页面单元 03：安全角色、资金边界与默认模式


![图19 - 实盘工作台总览](screenshots/19-live-real-overview.png)

*图19 - 实盘工作台总览。来源：生产路由 `/live-real`，5120×2880 PNG。*
BitPro 的默认策略运行语义是 paper/simulation。模拟盘可以使用真实市场数据、真实交易所元数据和真实模型预测，但账户余额、持仓、成交、盈亏、风控状态都来自 paper broker，不应从真实交易所账户派生。

涉及真实 OKX 私钥、账户余额、挂单和实盘订单的页面需要明确进入 `实盘` 工作台，并经过账户绑定、预检、部署确认等步骤。说明书中的实盘章节只解释页面用法和安全边界，不代表建议开启真实资金交易。所有 API Key、Webhook 和 token 都应只在受控环境保存，截图和文档不得暴露明文。

## 页面单元 04：首页：系统概览与行情入口


![图01 - 首页行情总览](screenshots/01-home-overview.png)

*图01 - 首页行情总览。来源：生产路由 `/`，5120×2880 PNG。*
首页用于让操作者快速判断系统是否具备研究条件。页面顶部展示行情概览和关键资产价格，中间区域聚合常用入口，左侧仍保留完整导航。若只是确认当前行情、进入某个功能页，首页是最短路径；若需要做策略评估，应继续进入行情、数据或回测页面查看更细粒度信息。

使用时先确认行情价格是否刷新，再看页面是否出现网络错误或服务不可用提示。生产截图中的行情表来自 OKX 公共市场数据，适合作为“页面连通性”和“市场基准”的第一层检查，但不能替代回测数据覆盖检查。

## 页面单元 05：行情页：交易对选择与实时行情


![图02 - 行情 K 线与订单簿](screenshots/02-market-kline-orderbook.png)

*图02 - 行情 K 线与订单簿。来源：生产路由 `/market`，5120×2880 PNG。*
行情页以交易对为中心组织数据。操作者可以切换 BTC/USDT 等交易对，查看最新价格、涨跌幅、成交量、K 线和盘口。页面适合用于确认策略标的的近期波动、趋势状态和流动性基础。

策略研发时，不要只看单个瞬间价格。应结合周期切换、AI 预测、订单簿和后续回测结果判断信号是否稳定。若页面没有最新 K 线或盘口为空，需要先检查数据管理同步和后端 market API。

## 页面单元 06：K 线图：周期、指标与趋势判断


![图02 - 行情 K 线与订单簿](screenshots/02-market-kline-orderbook.png)

*图02 - 行情 K 线与订单簿。来源：生产路由 `/market`，5120×2880 PNG。*


![图03 - 行情周期切换区](screenshots/03-market-timeframes.png)

*图03 - 行情周期切换区。来源：生产路由 `/market`，5120×2880 PNG。*
K 线区展示不同时间尺度的价格序列。短周期（如 1m、5m）适合观察微观波动和执行噪声，长周期（如 1h、4h、1d）更适合看趋势和策略级别方向。页面中的周期按钮只是观察维度，不会自动改变已有策略实例的运行周期。

使用时应先选定研究目的：做高频观察看短周期，做趋势策略验证看中长周期。若策略配置里有固定 timeframe，以策略配置为准；行情页切换周期主要用于人工检查，不直接改写策略。

## 页面单元 07：AI 预测区：预测线、置信与误差理解


![图02 - 行情 K 线与订单簿](screenshots/02-market-kline-orderbook.png)

*图02 - 行情 K 线与订单簿。来源：生产路由 `/market`，5120×2880 PNG。*


![图03 - 行情周期切换区](screenshots/03-market-timeframes.png)

*图03 - 行情周期切换区。来源：生产路由 `/market`，5120×2880 PNG。*
行情页的 AI 预测区当前处于 fail-closed 关闭状态：生产后端 `KAIROS_INFERENCE_ENABLED=false`、`SUPERPNL_INFERENCE_ENABLED=false` 时，预测模型不加载、不下载数据，`/market` 页面也不渲染 AI 预测开关或调用预测客户端。这是刻意的边界：历史 Kairos/SuperPnL 研究代码保留作回溯资料，但恢复生产推理必须经过代码评审和资源验证，且任何情况下都不得使用 mock、随机游走或模板动量数据替代真实模型输出。

若未来预测能力重新启用，看预测时重点比较三件事：第一，预测方向是否与近期趋势一致；第二，预测幅度是否超过手续费和滑点成本；第三，历史误差是否较大。若模型输出与订单簿、成交量或更长周期趋势矛盾，应降低信号权重，转入回测或模拟盘验证。

订单簿展示买盘、卖盘、盘口价差和局部深度。它用于判断当前价格是否容易成交，以及策略下单可能遇到的滑点。价差越宽、深度越薄，市价执行成本越高；对合约策略，低流动性还会放大强平和止损失效风险。

## 页面单元 20：策略如何执行：BaseStrategy 生命周期


![图12 - 模拟实例详情顶部](screenshots/12-live-instance-detail-top.png)

*图12 - 模拟实例详情顶部。来源：生产路由 `/live`，5120×2880 PNG。*
BitPro 的可运行策略通常继承统一的 `BaseStrategy`。初始化阶段读取 `self.config` 并准备窗口、状态和参数；启动后策略引擎按交易对和周期喂入确认后的 K 线 `BarData`；策略在 `on_bar` 中计算信号，决定是否调用现货 `buy/sell` 或合约 `open_contract/close_contract`。

执行链路可以概括为：策略定义 -> 策略引擎加载 -> 数据预热 -> 每根 K 线触发策略逻辑 -> broker 撮合 -> 成交/持仓/事件持久化 -> UI 轮询展示。策略代码不应在单根 K 线里回看未来数据，也不应混用现货和合约接口。

## 页面单元 21：策略执行图：从行情到成交记录


![图12 - 模拟实例详情顶部](screenshots/12-live-instance-detail-top.png)

*图12 - 模拟实例详情顶部。来源：生产路由 `/live`，5120×2880 PNG。*
以下流程帮助理解页面上的收益、持仓、成交和日志从哪里来。市场数据进入策略引擎后，策略只产生动作意图；真正的余额、成交、持仓和 PnL 由 broker 层计算并持久化。监控、模拟详情和信号中心再读取这些状态。

```mermaid
flowchart LR
  A[OKX/本地K线] --> B[StrategyEngine]
  B --> C[BaseStrategy.on_bar]
  C --> D{动作}
  D -->|现货 buy/sell| E[PaperBroker]
  D -->|合约 open/close| F[ContractPaperBroker]
  E --> G[trades/positions/events]
  F --> G
  G --> H[模拟详情/监控/信号]
```

如果某个页面指标异常，应沿这条链路定位：先看数据是否更新，再看策略日志，再看 broker 账户状态，最后看 UI 展示是否与 API 一致。

## 页面单元 27：回测成本模型：maker、taker 与滑点


![图08 - 回测创建向导](screenshots/08-backtest-create-wizard.png)

*图08 - 回测创建向导。来源：生产路由 `/backtest`，5120×2880 PNG。*
回测成本使用 bps 字段表达，而不是一个模糊费率。现货默认更高的 maker/taker 成本，USDT 永续默认更低的合约费率；滑点单独配置。当前市场成交通常按 taker 费率加滑点模拟，maker 字段保留给未来 limit/orderbook 型回测。

## 页面单元 56：现有策略优化：Paper 策略的改良闭环

现有策略优化会扫描正在运行且满足时长条件的 paper 策略，选择表现较差的源策略，让 AI 尝试改良参数或代码。优化候选通过 BaseStrategy 沙箱和统一回测后，会作为独立 paper 策略启动试运行。

## 页面单元 57：AI 模型、API Key 与无 mock 原则

## 页面单元 62：复盘中心：运行策略的小时级复盘

> 生产截图待按单元 61 复采规则采集；权威设计文档见 `docs/pages/复盘中心.md`。

复盘中心（`/review`）回答"现在跑着的模拟策略最近表现怎么样、为什么"。页面调用 `GET /api/v2/review/summary`，按窗口（默认 24h、可切 7d 等）和小时桶聚合运行中 paper 策略的收益、回撤和成交质量，输出分层评分榜单、表现最好/最差列表和收益热力图，并给出结论标签（如趋势贡献、成本拖累）。

使用要点：

- 评分只统计窗口内有真实权益采样和成交的策略；数据不足的策略显式标注，不补假分。
- 从榜单可以直接跳转到对应模拟实例详情做逐笔核对。
- 复盘结论是研究参考，不构成调仓指令；调整参数后应回到回测和模拟盘重新验证。

## 附录 A：关键术语

- Paper / Simulation：使用真实市场数据和模拟账户状态运行策略，不读取真实账户余额、持仓或订单。
- Backtest：使用真实历史 K 线对策略逻辑进行历史验证，指标不代表未来收益。
- Signal：策略产生的外部执行意图，需要通道、策略启用和可选人工确认后才可能发送。
- Live Trial：显式确认后的独立实盘试运行克隆，和 paper 源策略分离。
- BaseStrategy：BitPro 统一策略执行接口，策略通过 on_bar 接收 K 线并调用 broker API。
